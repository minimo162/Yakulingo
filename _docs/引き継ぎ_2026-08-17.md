死んだ経路、残る1か所は常に `-Style 'full'`）。

題材の「4/20」「11/20」は**経路の比較には使えるが、合否には使えない。**

### 3-4. 照合器を何度も壊した


### 6-3. 利用者に投げてある問い（未決）

**「利用者が略語を登録する仕組みは要るのか。市販ツールにあるか。」**

調べた結果は次のとおり。**この回では結論を出していない。**

- **市販ツールに、略語専用の登録簿は無い。** memoQ の termbase の項目は
  ID / Note / Project / Domain / Client / Subject / Definition / Matching /
  Case sensitivity / Forbidden / Example / POS / Gender / Number で、
  **略語は普通の用語（同義語）として入れ、`Case sensitivity` を Yes にする**
  （「TBD や XML のような略語に良い」と明記）。専用の記録型は無い
  （出典 https://docs.memoq.com/current/en/Concepts/concepts-term-bases-inside-an-entry.html ）
- **アプリ内でも、`AbbreviationEntries` の利用先は `Publication.ps1` だけ**である。
  翻訳・QC・用語集・書き出しは一切見ていない
- **用語集の `cell_exact` が既に同じ仕事をしている。** 註は
  「用語の一貫性ではなく**列からはみ出さないこと**の保証」と書いている
  （`CatProject.ps1:826`）
- **決定的な点。** 数字を含む略語（`上期→1H`、`2026年度→FY26`）は
  `numeric-value-extra`（error）で弾かれ、免除は
  **「利用者が登録した完全一致訳をアプリが一字一句写した場合」だけ**である
  （`CatProject.ps1:668-691`）。つまり**いちばん効く略語は、用語集経由でしか
  通せない。略語登録簿では通せない。**

**私の見立て**: 略語登録簿は用語集と重複しており、しかも本命の略語を通せない。
用語集へ畳むのが筋である。ただし `first_use_rule`（初出で綴る）だけは用語集に
無い概念なので、畳むならその扱いを決める必要がある。**利用者の判断を待つ。**
