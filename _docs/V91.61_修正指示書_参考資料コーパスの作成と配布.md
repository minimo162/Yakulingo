# V91.61 修正指示書: 参考資料コーパスの作成と配布（PDF → Markdown）

作成日: 2026-08-04 / 対象: V91.60 / 段階: **1**
（`要件整理_汎用翻訳アプリとRAG翻訳.md` §13-8 の段階1）

## この版の位置づけ

**参考資料の PDF を Markdown へ変換し、配布物として利用者へ届ける経路だけを作る。**

- **検索も文例注入も行わない。** 段階2以降。
- **翻訳の挙動を変えない。** プロンプト・用語集・翻訳経路に触れない。
- **一般利用者から見て、この版の変更点は何も無い。** コーパスがローカルへ増えるだけで、
  画面にも動作にも現れない。

### なぜ取り込みだけを切り出すか

取り込みが正しく動くことは、検索の良し悪しとは独立に確かめられる。
一緒に入れると、訳質が変わらなかったときに「検索が悪いのか、取り込みが悪いのか」を
切り分けられない。**先に、確かめられるほうを確かめる。**

## §1 設計の骨子 — 誰が何をするか

**アプリは共有フォルダへ書き込まない。** 書き込み権限の有無に関わらず、
書く経路を持たせない。これで同時実行の衝突も権限の差も最初から存在しなくなる。

| 役 | 操作 | 書き込み先 |
| --- | --- | --- |
| **管理者** | 管理画面で PDF を取り込む | **ローカル**（自分の端末） |
| **管理者** | 配布用フォルダを作る（既存の発行手順と同じ形） | **ローカル** |
| **管理者** | できたフォルダを共有フォルダへコピーする | 手作業（アプリは関与しない） |
| **一般利用者** | 何もしない | — |
| **アプリ（起動時）** | 版チェックのついでにコーパスをローカルへ複製する | **ローカル** |

**一般利用者にはコーパスの存在を知らせない。** 画面に出さない。設定項目も出さない。
段階2以降で訳質が上がるだけの、見えない仕組みとして扱う。

## §3 フォルダ構成

### §3-1 管理者の手元（取り込み中）

```
参考資料の原本フォルダ（管理者が決める。どこでもよい）
  ├─ 英文短信/
  │     2027-1Q_tanshin_en.pdf
  └─ 英文アニュアルレポート/
        AR2026_en.pdf

<データディレクトリ>/corpus-build/          ← 取り込み結果（ローカル）
  manifest.json
  英文短信/2027-1Q_tanshin_en.md
  英文アニュアルレポート/AR2026_en.md
```

`<データディレクトリ>` は `Get-YakuDataDir`（既定 `%USERPROFILE%\.yakulingo-ps`）。
**版更新で消えず、`YAKULINGO_DATA_DIR` を尊重する**（V91.59 の判断と同じ）。

### §3-2 共有フォルダ（発行後）

```
共有フォルダ（財務本部限定）
  ├─ current.txt              ← アプリの現行版（既存）
  ├─ V91.61/                  ← アプリ本体（既存）
  └─ corpus/                  ← 新規。コーパス配布物
        current.txt           ← コーパスの現行版（1行）
        2026-08-04/
           manifest.json
           英文短信/*.md
```

**コーパスはアプリとは別に版を持つ。** 資料が増えるたびにアプリの版を上げずに済む。
切り替えは `corpus/current.txt` の書き換えだけ。**アプリ本体の運用と同じ作法である。**

### §3-3 利用者の手元（配布後）

```
%LOCALAPPDATA%\YakuLingo\
  ├─ versions\<build>-<hash>\app\      ← アプリ本体（既存。版ごとに作られる）
  └─ corpus\2026-08-04\                ← 新規。コーパス（版ごと。N-1 まで保持）
        manifest.json
        英文短信/*.md
```

**`versions\<build>-<hash>\` の下へは置かない。**
アプリの版を上げるたびにコーパスを取り直すことになるため。

`bootstrap.ps1` がコーパスの場所を環境変数 `YAKULINGO_CORPUS_DIR` でアプリへ渡す。
**パス解決の重複を作らない。**

## §4 管理画面

### §4-1 到達方法

共有フォルダに管理者用のランチャーを置く。

```
共有フォルダ/
  YakuLingo起動.cmd            ← 一般利用者用（既存）
  管理者用_コーパス作成.cmd      ← 新規。-Admin 付きで起動する
```

- 一般利用者用のランチャーからは管理画面へ到達できない。UI に隠しリンクも置かない。
- **これは「見せない」ための仕切りであって、権限の制御ではない。**
  引数を知っていれば誰でも開ける。**コーパスの中身は財務本部内で共有してよいものに
  限る**（決定事項#11）ため、この強度で足りる。

### §4-2 画面

```
コーパス作成（管理者用）

  原本フォルダ: C:\work\参考資料             [参照]

  英文短信                取込済 12 件 / 未取込 3 件
  英文アニュアルレポート    取込済  2 件 / 未取込 0 件

  [未取込の3件を取り込む]

  ─────────────────────────────
  配布用フォルダを作る: [作成]
    → <データディレクトリ>\corpus-publish\2026-08-04\corpus\ を作ります。
       この corpus フォルダを共有フォルダへ丸ごとコピーしてください。
       （既に corpus がある場合は上書き＝統合。current.txt も入っています）
```

出来上がりは**共有フォルダへそのまま置ける形**にする。手順を1つに減らすため、
版フォルダだけでなく `corpus\` の器と `current.txt` までこちらで作る。

```
<データディレクトリ>\corpus-publish\2026-08-04\
  └─ corpus\                    ← これを共有フォルダの直下へコピーする
       ├─ current.txt           ← "2026-08-04"（書き換え不要）
       └─ 2026-08-04\
            ├─ manifest.json
            └─ 英文短信\*.md
```

以前は版フォルダだけを作り、`corpus\` と `current.txt` は管理者が手で用意する
決まりだった。実機で「配布用フォルダに corpus フォルダが見当たらない」となったため、
器ごと作る方式へ改めた。**覚える手順が少ないほど配布は事故らない。**

**「共有フォルダへコピーしてください」と表示して終わる。アプリは共有へ書かない。**
既存の `アップロード用フォルダ作成.cmd`（アプリ本体の発行）と同じ思想である。

## §5 取り込みの流れ（管理画面）

```
① 管理者が原本フォルダを指定する
② アプリが *.pdf を列挙し、corpus-build/manifest.json と突き合わせて未取込を出す
③ 管理者が「取り込む」を押す
④ ブラウザが1件ずつ処理する
     GET  /api/admin/corpus/pdf?id=...    PDF のバイト列を受け取る
     WASM で解析（ocrEnabled:false, outputFormat:'markdown'）
     POST /api/admin/corpus/ingest        Markdown を返す
⑤ サーバーが corpus-build/ へ .md を保存し、manifest.json を更新する
```

**ブラウザにフォルダを読ませない。** ブラウザ単体ではフォルダを列挙できないため、
**列挙・読み出し・保存はすべて PowerShell が行い、ブラウザは解析だけを担う。**

**すべてローカルへの書き込みである。** 共有フォルダには触れない。

## §6 実装

### §6-1 WASM の同梱

| 配置 | 内容 |
| --- | --- |
| `app/www/vendor/liteparse/liteparse_wasm.js` | 37 KB |
| `app/www/vendor/liteparse/liteparse_wasm_bg.wasm` | 5.3 MB |
| `app/www/vendor/liteparse/LICENSE` | Apache-2.0 の写し |

配布物の一部なので **`bootstrap.ps1` のローカル複製と一緒に来る**。
`New-YakuPackage.ps1` の manifest と SHA-256 検証にそのまま乗る。特別扱いしない。

**`Get-YakuMimeType`（`Server.ps1:1489`）へ `.wasm` を追加する。**

```powershell
'.wasm' { 'application/wasm' }
```

`WebAssembly.instantiateStreaming` が正しい MIME を要求するため。
配信できない環境向けに、JS 側は `ArrayBuffer` 経由の初期化へ落とせるようにしておく。

### §6-2 起動オプション

`Start-YakuLingo.ps1` へ `-Admin` スイッチを追加する。

- 既定は無効。**無効時は管理用の API と画面を登録しない**（存在しないのと同じにする）。
- 設定ファイルには保存しない。起動のたびに指定する。

### §6-3 管理用 API（`-Admin` のときだけ登録）

| メソッド | パス | 役割 |
| --- | --- | --- |
| GET | `/api/admin/corpus/status` | 原本フォルダの到達性、データベース一覧、取込済/未取込の件数 |
| GET | `/api/admin/corpus/pending` | 未取込 PDF の一覧（id・相対パス・サイズ） |
| GET | `/api/admin/corpus/pdf?id=...` | PDF のバイト列 |
| POST | `/api/admin/corpus/ingest` | `{id, markdown, pages, chars}` を受け取り保存 |
| POST | `/api/admin/corpus/publish` | `corpus-publish/<日付>/corpus/`（`current.txt` 込み）を作る |

**原本フォルダの外へ出ないことを、`Serve-YakuStaticFile` と同じ方式で検査する**
（`GetFullPath` して基準パスの前方一致を確認）。
`id` にパスそのものを使わず manifest の索引経由にするのは、
入力が直接ファイルパスにならないようにするためである。

### §6-4 manifest.json

```json
{
  "schema": "yaku-corpus-1",
  "corpus_version": "2026-08-04",
  "updated": "2026-08-04T12:00:00",
  "entries": [
    {
      "id": "a1b2c3d4",
      "database": "英文短信",
      "source": "英文短信/2027-1Q_tanshin_en.pdf",
      "sha256": "…",
      "markdown": "英文短信/2027-1Q_tanshin_en.md",
      "pages": 15,
      "chars": 30821,
      "status": "ok",
      "note": ""
    }
  ]
}
```

- `id` は `sha256` の先頭8桁。**同じ内容の PDF は名前が違っても同じ id になる。**
- `status` は `ok` / `low-text` / `failed`。
- 書き込みは `Write-YakuTextAtomic`（既存）を使う。
- **配布物には `.md` と `manifest.json` だけを入れる。元 PDF は入れない。**

### §6-5 保存する Markdown

WASM が返すページごとの markdown を、**ページ境界のコメントを挟んで連結する。**

```markdown
<!--yaku-page:1-->
Consolidated Financial Results ...

<!--yaku-page:2-->
...
```

段階2以降で「どの資料の何ページから引いたか」を示せるようにするため。
本文には手を加えない。

### §6-6 `bootstrap.ps1` へのコーパス複製の追加

アプリの版チェックの**後**に、同じ作法でコーパスを複製する。

```
共有 corpus/current.txt を読む
  → 未設定・到達不能なら何もしない（コーパス無しで起動する）
ローカル corpus\<版>\ が manifest どおり揃っていれば、そのまま使う
  → 揃っていなければ、共有からローカルへ複製し SHA-256 で検証する
環境変数 YAKULINGO_CORPUS_DIR にローカルのパスを入れてアプリを起動する
N-1 世代まで残し、それより古い版は削除する
```

**アプリ本体の複製と同じ手順を流用する。** 新しい仕組みを作らない。

| 判断 | 決定 |
| --- | --- |
| コーパスが無い / 落ちている | **何もせず起動する。** 警告も出さない（利用者は存在を知らない） |
| 複製に失敗した | 前の版がローカルにあればそれを使う。無ければコーパス無しで起動 |
| 起動時間への影響 | 差分が無ければ検証のみ。**版が変わったときだけ複製が走る** |

## §7 落とし穴として先に潰しておくこと

### §7-1 OCR を起動させない

`ocrEnabled: false` を必ず渡す。**渡し忘れると tessdata を GitHub から取りに行き、
社内網では失敗して取り込みが止まる**（要件整理 §13-1 で実測）。

`isComplex()` は**使わない。** 15ページ中10ページで `needsOcr=true` が立つのに、
OCR なしで全ページからテキストが取れた（同 §13-6）。信号として役に立たない。

### §7-2 抽出量が少ない資料を見分ける

ページあたりの抽出文字数が閾値（既定 200字）を下回るページが半数を超えたら、
`status: low-text` として記録し、管理画面に出す。
**エラーにはしない。** 画像主体の資料は正常に「取れない」だけである。

### §7-3 起動を遅くしない

- **一般利用者の起動経路に、取り込みの処理を一切入れない。**
- WASM の初期化（実測 369ms）は管理画面を開いたときに初めて行う。
  一般利用者は WASM を読み込まない。
- コーパスの複製は版が変わったときだけ走る。

### §7-4 配布物の肥大を避ける

コーパスは `.md` のテキストのみ。実測で 15ページの資料が 31KB。
100本でも 3MB 程度に収まる見込みだが、**`bootstrap.ps1` は全件を SHA-256 で
検証する**ため、件数が増えれば起動時の検証時間が伸びる。
**版が変わっていないときは検証を省く**（アプリ本体と同じ扱い）。

## §8 セキュリティ

| 経路 | 判定 |
| --- | --- |
| PDF の読み出し | 管理者のローカル。PowerShell → localhost → ブラウザ |
| 解析 | ブラウザ内の WASM。**外部通信なし**（要件整理 §13-6 で実測確認済み） |
| 取込結果の保存 | 管理者のローカル |
| 共有フォルダへの発行 | **管理者の手作業。アプリは書かない** |
| 利用者への配布 | 共有 → ローカルへの読み取りのみ |
| **Copilot への送信** | **この版では発生しない**（文例注入は段階2以降） |

**この版で外部へ出るものは何もない。**

段階2以降で文例を Copilot へ送るようになるため、**開示済み資料だけを入れて始める**
（決定事項#11）。過去 ECM 英訳は英語側の数値マスキング（段階5）を作ってから。

利用者のローカルへコーパスの写しが残るが、**利用者は財務本部の構成員であり、
元の資料そのものを扱える立場にある。**新しい露出にはならない。

## §9 受容基準

1. `-Admin` を付けずに起動したとき、アプリの挙動が V91.60 と**変わらない**こと
   （管理用 API が登録されず、画面にも設定にも現れないこと）
2. `.wasm` が `Content-Type: application/wasm` で配信されること
3. 管理画面で 15ページの PDF が **1秒以内**に取り込めること（実測値 692ms + 通信）
4. 取り込み中に**外部への通信が発生しない**こと（開発者ツールのネットワークで確認）
5. **OCR を起動しない**こと（tessdata を取りに行かない）
6. 同じ PDF を2回取り込んでも manifest のエントリが増えないこと
7. 別名で保存した同一内容の PDF が、同じ `id` に収束すること
8. 壊れた PDF で停止せず、`status: failed` を記録して次へ進むこと
9. 画像主体の PDF が `status: low-text` になり、管理画面に出ること
10. **アプリが共有フォルダへ一切書き込まないこと**（取り込み中も、起動時も）
11. 「配布用フォルダを作る」がローカルへ出力し、**共有への反映方法を画面に表示する**こと。
    出力は `corpus\` の器と `current.txt` を含み、**共有フォルダへコピーするだけで**
    `bootstrap.ps1` が版を解決できること（管理者に `current.txt` を書き換えさせない）
12. `bootstrap.ps1` が共有の `corpus/current.txt` を読み、ローカルへ複製し、
    SHA-256 で検証すること
13. コーパスが**無い / 到達できない / 壊れているとき、アプリが通常どおり起動する**こと
14. **アプリの版を上げてもコーパスの再複製が発生しない**こと
    （`versions/<build>-<hash>/` の下に置かない）
15. コーパスの版だけを上げたとき、アプリの版を変えずに切り替わること
16. コーパスが N-1 世代まで保持され、それより古い版が削除されること
17. `YAKULINGO_DATA_DIR` を設定したとき、取込結果がその配下へ行くこと
18. 配布物が 5.2MB 増え、`Test-YakuPackage.ps1` が通ること
19. 既存の回帰（Check-Encoding / 数値マスキング / 設定パス / bootstrap / V91.7 / V91.10 / V91.17）が
    すべて通ること
