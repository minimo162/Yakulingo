# V91.37 修正指示書 — 数値単位の前処理置換（oku統一）・監査簡素化・数値規則縮小

ベース: V91.36（数値整合監査・構文エラー修正版）
対象: 前処理関数の新設（テキスト・ファイル両経路の共通部）/
      数値整合監査の簡素化 / PromptBuilder.ps1 numeric_rules の縮小 /
      単体テスト
方針: モデルに単位変換の算術をさせない。送信前にアプリ側（決定論
コード）で日本語数値単位を英語トークンへ置換し、モデルの仕事を
「トークンをそのまま運ぶ」に純化する。一発成功率を上げ、監査は
発火しない保険に降格する。表記は **oku 単独に統一**（ECM様式準拠、
ユーザー決定）。

## 1.【必須】前処理置換関数 — Convert-YakuNumericUnits（新設・共通）

### 置換規則（適用順に。数字列 = [\d][\d,\.]* 、直前に数字必須）
| 原文パターン | 置換 | 例 |
|---|---|---|
| N兆M億円（複合） | 合算して `{N×10000+M} oku` | 1兆1,577億円 → 11,577 oku |
| N兆円 | `{N×10000} oku` | 2兆円 → 20,000 oku |
| N億円 | `{N} oku` | 5,602億円 → 5,602 oku / 2.5億円 → 2.5 oku |
| N万台 | `{N×10} k units` | 100万台 → 1,000 k units |
| N千台 | `{N} k units` | 659千台 → 659 k units |
| N万円 | `{N×10} k yen` | 410万円 → 4,100 k yen |
| N千円 | `{N} k yen` | 575千円 → 575 k yen |

- **符号は触らない**: ▲/△/(…) は置換対象の外に置き、括弧化・up/down
  変換の判断は従来通りモデル側規則に残す（この層は安定稼働中）。
- **数字必須**: 「数億円」「十数億円」「億円単位」等は `\d` 直前条件で
  自然に対象外（従来通りモデルが several oku 等と訳す）。
- **マスク互換**: `xxx億円`・`XXX億円` も置換対象に含める
  （`(?:[\d][\d,\.]*|[xX]{2,})` をトークンとし、xxx系は×10等の算術
  不能のため 万台・万円・兆円では**置換せず警告ログ**——マスク値の
  桁曖昧性を無言で通さない。億円・千台・千円は無変換なので置換可）。
- 万円の×10で小数が出る場合（5,752千円系の原文は千円なので通常
  発生しないが 0.5万円→5 k yen 等）は整数化できる時のみ置換、
  できない場合は無置換＋警告。
- 適用位置: テキスト翻訳・ファイル翻訳の**バッチ組立前**（CharCount・
  expectedChars・用語集マッチは置換後テキストに対して行われる）。

### 表記の統一（oku yen → oku）
- 置換先は `oku`（yenなし）。ECM様式で許容・使用されている表記に
  資料横断で揃える（ユーザー決定）。
- FULL/BRIEFの層別はしない（両方 oku）。

## 2.【必須】数値整合監査の簡素化

前処理後は期待値の導出計算が不要になり、監査は
「**置換で生成した英語トークン文字列が出力に存在するか**」の突合に
単純化できる:
1. 前処理関数が置換時に生成トークン一覧（"5,602 oku" 等）を返す
2. 監査は FULL/BRIEF それぞれで各トークンの存在（と出現回数）を確認
3. 不一致時の挙動は現行維持（scale-error分類→RETRY→
   NUMERIC_SCALE_MISMATCH）だが、発火は「モデルがトークンを落とした/
   改変した」場合のみとなり、リトライ頻度は実質ゼロ化を見込む
4. ％の突合は従来通り（前処理対象外のため）
5. ログ書式（checked/matched/scaleErrors）は互換維持

## 3.【必須】numeric_rules の縮小 — PromptBuilder.ps1

前処理化により**数値換算の規則群が不要**になる。削除:
- 万円=k yen の換算例（575万2,000円 等）
- 億円 verbatim 反例（V91.35 §0-1 で追加した行）
- 兆円×10,000 の記述
- Units行の該当部分

置き換え（1行）:
```
- Numeric tokens already in English (oku, k units, k yen) : keep the
  number and unit verbatim; never rescale, re-convert, or restore
  Japanese units. Signs and % follow the existing rules.
```
- million/billion/trillion 禁止は維持（モデルが自発的に換算し直す
  芽を摘む）。
- 総語数上限を **1,270語** に更新（換算規則の削除で純減）。

## 4. 単体テスト（前処理は決定論なのでテストで完全に守る）

Convert-YakuNumericUnits に対する必須ケース:
1. 15年前1H文書（億円9件・千台4件・%）→ 期待置換結果と完全一致
2. Q3文書（億円8件・千台4件・強調【】共存）→ 同上
3. 人工ケース: 1兆1,577億円 / 2.5億円 / 100万台 / 数億円（無置換）/
   xxx億円（置換）/ xxx万台（無置換＋警告）/ ▲638億円（符号外置換:
   ▲638 oku）/ 10〜20億円（両数字置換）
4. 置換前後で数字列・符号・%・【】・マスキングトークンに差分がない
   こと（置換対象以外の不変性）

## 受入基準

1. 3文書（1H・Q3・本命マスク版）のエンドツーエンドで、監査が全件
   matched・**リトライ発生ゼロ**で完走する（scaleErrors=0 が常態化）
2. 出力の金額表記が oku に統一される（oku yen が出ない。プロンプト
   側の残存記述・用語集・回帰テスト期待値も oku へ更新）

   出る（無言の桁曖昧を許さない）
4. 単体テスト全ケースパス、Prompt-Regression-Test.ps1 全件パス
   （期待値のoku更新込み）
5. プロンプト総語数 1,270語以下
