# 設計: コーパスと翻訳メモリを1つにする（2026-08-17）

利用者の要求。

> コーパスと翻訳メモリに分かれているのは開発の都合上そうなってしまっただけで、
> 本来は分けてはいけないと思う。
> 最初は対訳の対を作る方法がわからなかったから、対にしなかっただけで、
> 対が作れるなら対だけでよい。また、管理者しか触れないというのも、あくまで
> 開発途中だったから正式版に入れなかったというだけ。

**要求は正しい。ただし「改名で済む」ではない。** 実装を読んで分かった差を先に置く。

## 1. いま何が分かれているか（実装を読んだ結果）

4世代の設計が積み重なっている。

```
Corpus.ps1          段階1  管理者がPDFを取り込む → 英語Markdown＋台帳
CorpusSearch.ps1    段階2  「コーパスは英語側だけ。日本語との対応づけは持たない」
CorpusReference.ps1 段階3  日本語から引く橋渡しを Copilot に作らせる（Agentic RAG）
CorpusPairs.ps1     後発  「対が取れるようになったので、その結果をここへ貯める」
TranslationMemory   確定した訳（日英の対）
```

**段階2の前提が、後発の CorpusPairs で崩れている。** 対が作れるなら、英語だけの
コーパスと、そこへ橋を架ける Agentic RAG は回り道である。利用者の言うとおり。

## 2. しかし、対の「信用の度合い」が違う

これは開発の都合ではなく、実質の差である。

| | 翻訳メモリ | 対訳の対（CorpusPairs） |
| --- | --- | --- |
| 記録 | `origin_project_id` `origin_segment_id` `origin_file_name` `origin_location` `origin_page` `review_revision` `reference_id` | `key` `database` `source` `ja` `en` `verified` `public` |
| 検証 | **`reference_id` を再計算して合わなければ弾く**（出典検証） | `source` は資料名の文字列。`verified` は数値の裏取りが通ったか |
| 意味 | **この資料のこの行を、人が確定した** | 対応していそうだと**道具が判断した** |
| 役割 | 利用者に「似ている過去の訳」として出し、**押して入れられる** | Copilot へ渡す参考例。**利用者の目には触れない** |

**素直に混ぜると、機械が推測した対が確定訳の顔をして利用者の前に出る。**
アプリの決まり（数値が抜けた訳は警告ではなく欠陥）と同じ強さで守るべき性質である。

## 3. 市販ツールの答え（実測）

Smartcat の事前翻訳の規則に **`Minimum TM segment Quality`** があり、既定は
`Reviewed` だった（2026-08-16 に実機で確認。`Minimum match percentage` と並んでいる）。
つまり**1つの記憶に品質の段を持たせ、規則が段で絞る**形である。
記憶を分けるのではなく、段で分ける。

（段の選択肢そのものは未測定。開いていない。）

## 4. 採る形

**1つの資産に、段を持たせる。**

```
確定       人が確定した訳。出典検証つき。押して入れられる
突合せ     日英の資料から機械が対にしたもの。数値の裏取りが通ったものと通らないもの
取り込み   まだ対になっていない本文（既存のコーパス）
```

- 引くのは1本の道にする。呼ぶ側は「過去の訳を探す」だけを知っていればよい
- **段は消さない。候補の札に出す。** 一致率の札（100% / 85-99% / 85未満）と同じ場所で、
  「確定」か「突合せ」かが目で分かるようにする
- 事前翻訳（`翻訳メモリで下訳する`）が自動で入れてよいのは**確定だけ**。
  突合せは候補に出すが、自動では入れない
- 管理者だけの制限は外す。利用者が自分の資料で対を作れるようにする
- `public` は配布に含めてよいかの印として残す（内部資料を配布に混ぜない）

## 5. まだ決めていないこと

- **既存のコーパス（英語Markdown）をどうするか。** 対にできるものは対にし、
  できないものを残すか、切るか。切ると段階3の Agentic RAG も消える
- 段の名前（利用者に見せる言葉）
- 突合せの対を、事前翻訳の対象にできる設定を置くか（Smartcat はそうしている）

## 6. なぜ先に書いたか

信用の境目を動かす変更である。**「開発の都合で分かれていた」と「実質が違う」を
取り違えたまま実装すると、機械が推測した訳が確定訳として書き出される。**
利用者の要求（1つにする・利用者が触れる）は満たしつつ、段で守る形にしたい。
