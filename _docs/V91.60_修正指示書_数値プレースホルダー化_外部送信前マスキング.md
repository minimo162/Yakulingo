# YakuLingo V91.60 修正指示書（Copilot送信前の数値プレースホルダー化）

作成日: 2026-08-03 / ベース: V91.59

利用者からの依頼: **Copilot への依頼は外部サーバーへの送信になるため、年号や
「1株当たり」のような機密性のない数値を除き、数値はすべてプレースホルダーに
置き換えて送信し、受信後に復元してほしい。**

本版は送信内容の機密性に関わる変更であり、翻訳品質契約より優先される。

- §1: マスク対象と非対象の定義
- §2: プレースホルダー記法
- §3: マスキングの適用位置
- §4: 符号・括弧の扱い（プロンプトからコードへの移管）
- §5: プロンプトの変更
- §6: 監査と再試行の変更（**平文数値の再送を止める**）
- §7: キャッシュ
- §8: 診断・ログ
- §9: UI と設定
- §10: 受容基準
- §11: 対象外・既知の限界
- §12: 実装順序と検証

## 背景: 現状で外部へ出ている数値

実装を確認した結果は次のとおり。仕様はこの事実の上に組む。

### 送信経路は2つ

| 経路 | 前処理 | 該当箇所 |
| --- | --- | --- |
| テキスト翻訳 | `Convert-YakuNumericUnits` → バッチ分割 → プロンプト | `Translation.ps1:1282` |
| ファイル翻訳 | 項目ごとに `Convert-YakuNumericUnits` → バッチ → プロンプト | `FileTranslation.ps1:1881` |

### Excelの数値セルは送信されていない

`Test-YakuShouldTranslateCell`（`FileProcessors.ps1:80-104`）が、数値・記号だけの
セル、日付、通貨表記、メール、URL、型式風トークンを翻訳対象から除外している。
`to_en` では日本語を含むセルだけが対象になる。

したがって**露出しているのは「日本語テキストの中に埋め込まれた数値」だけ**である。
表の数値セルはもともと送信されていない。本版の対象はこの埋め込み数値に限られる。

### 既存の数値前処理は「単位の英語化」であって秘匿ではない

`Convert-YakuNumericUnits`（`Translation.ps1:315-360`）は `72億円` → `72 oku`、
`1,234万円` → `12,340 k yen`、`5万台` → `50 k units` のように**単位だけ**を英語化する。
数値そのものは平文のまま送信される。

### 既存のマスキングは利用者の手作業

`Get-YakuMaskingPlaceholderTokens`（`Translation.ps1:300-303`）が拾うのは
`【…非開示】` という**利用者が自分で書いた**印である。`Convert-YakuNumericUnits` が
受け付ける `xx` / `xxx` も同様に手入力を想定している。
`Test-YakuMaskingPlaceholderIntegrity` はそれが往復で保たれたかを検証するだけで、
自動でマスクする機構は存在しない。

### 再試行時に平文数値をプロンプトへ載せている（要対処）

`New-YakuNumericCorrectionInstruction`（`Translation.ps1:414-421`）は
「`72 oku` というトークンを正確に出力せよ」という指示文を組み立て、
`Translation.ps1:962`、`FileTranslation.ps1:1684`、`FileTranslation.ps1:1967` から
**再送プロンプトへ連結している**。

本文をマスクしても、この経路から平文数値が出る。§6で必ず塞ぐ。

### 記法の衝突に注意すべき既存要素

| 記法 | 用途 | 該当箇所 |
| --- | --- | --- |
| `[[ID:n]]` | ファイル一括送信の項目ID | `FileTranslation.ps1:145` |
| `【…非開示】` | 利用者による手動マスク | `Translation.ps1:302` |
| `{key}` | プロンプトテンプレート変数 | `PromptBuilder.ps1:584` |
| `＜＞`（全角） | 見出し構造の照合。半角 `<>` はCopilotのレンダラーがHTMLタグとして隠す（V91.1） | README |

## §1 マスク対象と非対象の定義

### マスクしない（機密性なし）

| 種別 | 例 |
| --- | --- |
| 西暦・和暦の年 | `2026年`、`FY2026`、`令和8年`、`26/3期`、`2026年度` |
| 四半期・期・半期 | `第1四半期`、`1Q`、`Q1`、`上期`、`下期` |
| 月・日 | `4月`、`3月末`、`4/1` |
| 「1株当たり」等の定型句に含まれる1 | `1株当たり`、`一株当たり`、`1台当たり`、`1件当たり` |
| 箇条書き・見出しの番号 | `1.`、`(1)`、`①`、`第2章` |
| 製品名・型式に含まれる数字 | `CX-90`、`MX-30` |
| 法令・規格・条番号 | `第3条`、`ISO 9001` |
| バージョン番号 | `V91.60` |

### マスクする（機密性あり）

| 種別 | 例（前処理後） |
| --- | --- |
| 金額 | `72 oku`、`1,234 k yen`、`350円` |
| 数量 | `50 k units`、`120台`、`38件` |
| 比率・率 | `12.3%`、`▲3%` |
| 増減額・増減率 | `+72 oku`、`▲5.2%` |
| 構成比・シェア | `28%` |
| 上記に当てはまらない裸の数値 | `1,250` |

### 判断に迷う数値は既定でマスクする

分類器が確信を持てない数値は**マスク側に倒す**。誤ってマスクしても訳文は
プレースホルダー経由で復元されるため実害は小さいが、誤って平文で送ると
取り返しがつかない。

### 「1株当たり」の扱い

「1株当たり」の `1` は非機密だが、**その直後に続く金額は機密**である。

```
1株当たり配当金は 120円 です。
→ 1株当たり配当金は 【N1】 です。      （1 は残し、120円 をマスク）
```

`1株当たり` は定型句として文字列一致で除外し、金額側は通常どおりマスクする。

## §2 プレースホルダー記法

`【N1】`〜`【Nn】`（全角隅付き括弧 + `N` + 通し番号）を採用する。

採用理由:

- 既存の `【…非開示】` と同じ文字クラスであり、モデルが「触ってはいけない塊」として
  扱う実績がある。
- `[[ID:n]]` と文字が重ならない。ファイル一括送信の項目IDと取り違えない。
- 半角山括弧のようにCopilotのレンダラーに隠されない（V91.1で確認済みの問題を回避）。
- Excelへ書き戻しても数式化しない（先頭が `=` `+` `-` `@` でない）。
- `{key}` のテンプレート展開（`PromptBuilder.ps1:584` の `\{(\w+)\}`）と衝突しない。

番号は**1バッチ内で一意**。バッチをまたいで再利用しない。

利用者が自分で書いた `【…非開示】` とは正規表現で区別できる（`【N\d+】` と
`【[^【】]*非開示】`）。両者は共存させる。

## §3 マスキングの適用位置

**`Convert-YakuNumericUnits` の直後、バッチ分割の前**に置く。

```
原文
 → Convert-YakuNumericUnits      単位の英語化（億円→oku、兆円→oku換算）
 → New-YakuNumericMaskMap        ★新規: 数値をプレースホルダーへ
 → バッチ分割 → プロンプト → Copilot
 → 応答パース
 → Restore-YakuNumericMask       ★新規: プレースホルダーを復元
 → 訳文
```

単位変換を先に行う理由: `3兆2,000億円` → `32,000 oku` のような**桁の換算**を
伴うため、先にマスクすると換算できなくなる。単位を英語化してから
「数値 + 単位」をまとめて1トークンとしてマスクする。

### 新規関数（`Translation.ps1`）

```
New-YakuNumericMaskMap -Text <string> -Direction <to_en|to_jp> -Location <string>
  → @{ Text = マスク済みテキスト
       Map  = @{ '【N1】' = @{ Rendered='(72) oku'; Source='▲72億円' }; ... }
       MaskedCount = int
       KeptCount   = int }

Restore-YakuNumericMask -Text <string> -Map <hashtable>
  → 復元済みテキスト

Test-YakuNumericMaskIntegrity -MaskedSource <string> -Translated <string> -Map <hashtable>
  → @{ Ok; Missing=@(); Extra=@(); Detail }
```

`Map` は**プロセス内のみ**で保持し、ディスクにもキャッシュにも書かない（§7、§8）。

### 適用方向

**`to_en` / `to_jp` の両方向に適用する。** 現行の `Convert-YakuNumericUnits` は
`to_en` のみだが（`Translation.ps1:1282`、`FileTranslation.ps1:1878`）、
機密性は方向に依存しない。英語資料の数値も同じく外部へ出る。

`to_jp` では単位変換を行わないため、マスキングだけを適用する。

## §4 符号・括弧の扱い（プロンプトからコードへの移管）

現行は**プロンプトで**数値の整形を指示している（`PromptBuilder.ps1:565-568`）。

```
- ▲, negative minus signs, or マイナス: put parentheses around the numeric token only
- Positive/additive amounts marked +, ＋, or プラス keep +N.
```

マスク後はモデルが数値を見ないため、この指示は機能しない。
**符号を含めて1トークンとしてマスクし、復元時にコード側で英語表記を決める。**

| 原文 | 単位変換後 | 送信 | 復元 |
| --- | --- | --- | --- |
| `▲72億円` | `▲72 oku` | `【N1】` | `(72) oku` |
| `+72億円` | `+72 oku` | `【N2】` | `+72 oku` |
| `▲3%` | `▲3%` | `【N3】` | `(3) %` |
| `72億円` | `72 oku` | `【N4】` | `72 oku` |

これは副次的な改善でもある。整形をコードで決めるため、
モデルの揺れによる括弧の付け外しが原理的に起きなくなる。

### 増減動詞との二重表現

V90.6 で「増益・減益等の方向語が原文の `+` / `▲` を吸収し、数値を符号なしの
大きさに統一する」規則を入れた。これは**文脈依存**であり、コード側では
方向語の有無を判断できない。

本版では**原文の符号をそのまま復元する**方針とし、方向語との二重表現の
可能性は §11 の既知の限界として残す。プロンプト側には
「`【N…】` の前後に増減の方向語がある場合でも、`【N…】` は改変しない」とだけ指示する。

## §5 プロンプトの変更

### `Get-YakuNumericRulesSection`（`PromptBuilder.ps1:560-570`）を差し替える

削除する指示（マスク後は無意味、かつモデルを混乱させる）:

- `▲` の括弧化、`+N` の保持
- `oku` / `k units` / `k yen` の逐語保持、rescale 禁止、`million`/`billion` 禁止

新しい指示（要旨、英語で記述する）:

```
- Tokens of the form 【N1】, 【N2】 … are protected placeholders.
  Reproduce every placeholder exactly as written, the same number of times as
  the source. Never translate, reword, reorder within the token, split, merge,
  or drop them. Never invent a placeholder that is not in the source.
- A placeholder stands for a number with its unit and sign. Do not add units,
  currency words, parentheses, or signs around it.
- Words such as increase / decrease may appear next to a placeholder.
  Keep the placeholder unchanged regardless.
```

残す指示: `→` の再現条件、`YoY` / `QoQ` / `CAGR` / `Jan. to Dec.` の保持。

### 発火条件

現行の発火条件（`PromptBuilder.ps1:562`）は数値・記号の存在を見ている。
マスク後の本文に数値は残らないため、**`【N\d+】` を含むこと**を条件に変更する。

### 対象プロンプト

`prompts/text_translate_to_en.txt`、`text_translate_to_jp.txt`、
`file_translate_to_en.txt`、`file_translate_to_jp.txt`、`style_brief_rules.txt` の
うち、数値整形に言及している箇所を洗い出して同様に置き換える。

## §6 監査と再試行の変更

### `Test-YakuNumericIntegrity` は役割を失う

`Test-YakuNumericIntegrity`（`Translation.ps1:395-412`）は「送信した数値トークンが
訳文に残っているか」を検証する。マスク後の経路には平文数値が存在しないため、
`Get-YakuNumericAuditExpectations` は何も拾わず、監査は常に `checked=0` になる。

→ **プレースホルダー整合の検証に置き換える。** `Test-YakuNumericMaskIntegrity` が
「原文にある `【N…】` が訳文に同じ数だけあるか」「原文にない `【N…】` が
混入していないか」を検証する。呼び出し位置は現行の数値監査と同じ
（`Translation.ps1:913, 953`、`FileTranslation.ps1:1679, 1689, 1962, 1972`）。

### `New-YakuNumericCorrectionInstruction` から平文数値を除く（必須）

現行は期待するトークンを本文に書いて再送している。

```
- 72 oku: include the token 72 oku exactly as written; it is currently missing.
```

これは**マスキングの目的を無効化する**。プレースホルダー名だけを伝える形へ変更する。

```
PLACEHOLDER CORRECTION (mandatory): The following placeholders are missing from
your translation. Reproduce each of them exactly once, in the position where the
source has it. Do not change any other wording.
- 【N3】
- 【N7】
```

### 復元順序

**プレースホルダー検証に通ってから復元する。** 検証前に復元すると、
欠落したプレースホルダーが「数値が消えた訳文」として確定してしまう。

再試行上限に達しても復元できない場合は、既存方針（V91.42「翻訳経路に新たな
throw を増やさない」）に従い、**訳文を返しつつ確認警告を出す**。
未復元のプレースホルダーは原文の数値表記へ機械的に置き換え、
警告カテゴリ `numeric-placeholder-unresolved` を付ける。

### `Test-YakuMaskingPlaceholderIntegrity` は残す

利用者が自分で書いた `【…非開示】` の検証は用途が異なるため、別関数として残す。
検出正規表現 `【[^【】]*非開示】` は `【N1】` にマッチしないため衝突しない。

## §7 キャッシュ

`Get-YakuTranslationCacheStore`（`Translation.ps1:41-54`）はプロセス内メモリの
ハッシュテーブルで、ディスクには書かれない。

### キーと値の両方をマスク済みにする

- **キー**: マスク後テキスト（`FileTranslation.ps1:1898` および `Translation.ps1` のテキスト経路で
  `Get-YakuTranslationCacheKey -Text` へ渡す値をマスク後にする）
- **値**: マスク済み訳文。復元は取り出すたびに、その回の `Map` で行う。

副次効果として、**数値だけが違う定型文がキャッシュにヒットする**。
「売上高は【N1】でした」のような表項目・定型文が多い資料ではヒット率が上がる。

### 契約フィンガープリントの更新

`Get-YakuTranslationContractFingerprint`（`Translation.ps1:73-115`）の対象に
マスキング仕様のバージョン識別子を含め、**旧キャッシュを確実に無効化する**。
マスクなしで生成された訳文がマスク経路で再利用されると、復元が壊れる。

---

## §8 診断・ログ

- **`Map`（プレースホルダーと平文数値の対応）をログ・診断ファイル・キャッシュへ
  書かない。** 出力してよいのは件数のみ。
- 送信ペイロードを記録する診断は、**マスク後のテキストだけ**を記録する。
- `full_text_diagnostics_enabled`（既定 `false`）が有効なときの原文保存は
  ローカル限定なので現行どおりでよいが、原文と `Map` を同じ場所に並べない。
- 通常ログに出す情報: `masked=12 kept=3 restored=12 unresolved=0`。

---

## §9 UI と設定

### 設定項目を作らない

`numeric_masking_enabled` のような設定は**作らない**。機密要件は利用者が
個別に無効化できるべきではない。常時有効とする。

検証・回帰テスト用の抜け道としてのみ、環境変数 `YAKULINGO_NUMERIC_MASKING`
（`off` で無効）を用意する。設定画面には出さない。

### 表示

- 翻訳結果に「数値 12 件をマスクして送信しました」を表示する。
- 復元できなかったプレースホルダーがある場合は確認警告として明示する。
- 起動時のヘッダ、または設定画面の説明に「数値はマスクして送信します」を明記する。

## §10 受容基準

1. `to_en` / `to_jp` の両方向で、Copilot へ送信するプロンプトに §1 のマスク対象
   数値が平文で含まれないこと。**送信ペイロードを直接検査して確認する。**
2. 年号・四半期・箇条書き番号・型式（`CX-90`）・「1株当たり」の `1` が
   マスクされずに残ること。
3. 訳文で `【N…】` が原文と同じ数だけ再現され、復元後の数値が原文と一致すること。
4. `▲72億円` が `(72) oku`、`+72億円` が `+72 oku` へ復元されること。
5. 再試行プロンプト（`New-YakuNumericCorrectionInstruction`）に平文数値が
   含まれないこと。
6. キャッシュのキー・値ともにマスク済みで、`Map` が保存されないこと。
7. マスク仕様の変更が契約フィンガープリントに反映され、旧キャッシュが無効化されること。
8. プレースホルダーが復元できない場合でも翻訳が完走し、確認警告が出ること
   （新たな throw を増やさない）。
9. 診断ファイル・ログに `Map` が出力されないこと。
10. 既存の `【…非開示】` の手動マスクが従来どおり機能すること。
11. Excelの数値セル・日付セルが従来どおり送信対象外であること。

### 新規回帰テスト

`app/tools/Test-YakuV9160NumericMasking.ps1` を追加する。

- 分類: §1 の各行を最小例文で検証（マスクされる / されない）
- 往復: マスク → 疑似応答 → 復元 で原文の数値が戻ること
- 符号: `▲` / `+` / `%` の復元形
- 漏洩: 生成された送信ペイロードに平文数値が含まれないこと（**最重要**）
- 再試行: 補正指示文に平文数値が含まれないこと
- 異常系: プレースホルダー欠落・重複・混入時の挙動

## §11 対象外・既知の限界

### 数値マスキングは送信内容を非機密化しない

**本版は「数値」だけを秘匿する。**社名、製品名、施策名、組織名、そして
文章そのもの（何がどう増減したかの説明）は平文で送信される。

「営業利益は【N1】の減益となり、主因は【N2】の材料費高騰である」という文は、
数値を伏せても事業内容を開示している。

依頼どおりの実装を進めるが、**送信内容全体の機密性を担保するものではない**点は
利用者・依頼元と共有しておく必要がある。文章自体の秘匿が必要なら、
外部サーバーを使わない構成の検討が別途要る。

### その他の限界

- **訳質の低下**: モデルが数値の大小・単複を判断できなくなるため、
  `a decrease of 【N1】` のような冠詞・単複の選択が不安定になりうる。
  §12 の比較検証で影響を測る。
- **増減動詞との二重表現**: §4のとおり、方向語が符号を吸収する V90.6 の規則は
  コード側で判断できない。
- **文中で数値が並べ替わる訳**: 「AはBより大きい」型の比較で語順が変わると、
  プレースホルダーの位置は正しくても対応関係が入れ替わる可能性がある。
  検証では対応関係まで確認する。
- **BRIEF の圧縮**: BRIEF は原文の20〜30%へ圧縮するため、数値そのものが
  落ちることがある。プレースホルダーの欠落がモデルの省略なのか事故なのかを
  区別できない。BRIEF では欠落を警告に留め、エラーにしない。
