# YakuLingo ロードマップ

2026-08-08 時点

## 何を解こうとしているか

利用者が挙げた課題（2026-08-08）。これが基準であり、機能はここに紐づかない限り足さない。

1. **短い訳の品質が低い** — 英語が日本語の意味とずれる。用語集の機械置換と
   Copilot の英訳で訳が揺れる
2. **単なる翻訳機であって CAT ツールではない** — 原文と訳文の整合を確認しにくい。
   さきほど訳した文と今訳した文が整合しているか分からない
3. **過去の翻訳例が見れない** — 公表した英訳も、自分の英訳も
4. **英文短信・英文有報向けの翻訳もできるようにしたい**

## 決めた線引き

**簡易翻訳は読むだけ。書かない。**

| | 簡易翻訳 | CAT |
| --- | --- | --- |
| 訳す | ○ | ○ |
| 3つの書き方を出す | ○ | 資料ごとに1つ選ぶ |
| 推敲の往復（記録しない） | ○ | ○ |
| 公表訳の引用（読む） | ○ | ○ |
| 翻訳メモリ（書く） | × | ○ |
| 機械的な検査 | × | ○ |
| 確定・保存・再開 | × | ○ |

判断に迷ったら「溜まるかどうか」で決める。溜まるものは CAT。

## 済んだこと

### 安全に関わるもの

- CAT 経路が数値をマスクせずに送っていたのを直した。ファイル翻訳タブを廃止して
  全員を CAT へ寄せた直後だったので、最も機密性の高い作業が最も無防備な経路を
  通っていた
- 統制テストが「どのファイルが Copilot を呼ぶか」しか見ておらず、呼び出し元ごとの
  マスクを確かめていなかった。呼び出し元ごとに確かめるようにした
- 固有名詞のマスク。人名・法人名・地名は読みが自明でないものが多く、Copilot に
  任せると揺れる。送る前に置き換えて返ってから戻す
- 作業中の元ファイルが1時間で消えていた。利用者自身の操作が削除を起こし、
  丁寧に見た人ほど確実に失敗する構造だった
- 短い訳から数値が抜けるのを、警告ではなく欠陥として扱うようにした

### CAT の作り

- 作業内容をディスクへ保存し、続きから再開できる
- 確定の状態を作り、進捗を「人が確認した数」で数える
- 絞り込みを「すべて／未確認」の2つに。未翻訳は未確認に含まれる
- 事前翻訳を名前の付いた作業にした。押す前に対象の件数が見える
- 個人用の用語集。行から追加でき、配布分より優先する
- マウスだけで進められる
- 候補ペインに3種類（自分の訳・公表訳・用語集）

### 品質の土台

- 略語の採否を「綴ると入らない」かつ「一般的」の2基準で決めた
- 略語をモデルに選ばせず、一覧にあるものだけをアプリが当てる
- 3つの訳を立場で作り分ける（素直な訳・社内向け・公表向け）
- 抽出で段組みを分ける。統合報告書の連結が 60% → 2%

### 過去の翻訳例

- 対訳コーパス 2,308組。日本語で引ける
- 突き合わせを CAT の画面から行える
- 翻訳メモリ（CAT で確定したものが溜まる）

### 画面

- タブを「すぐ訳す／見比べて訳す」に。ファイル翻訳を廃止
- 用語を揃えた（コーパス→文例、セグメント→行、記憶→自分の訳）
- 訳の見せ方を「答え1つ＋添え物」に。字数を添える
- 再描画で位置・フォーカスを保つ
- 出力先を開くボタン
- Copilot 自身のエラーをそのまま伝える

## これからやること

### 第1段階 — 決めたが作っていないもの

1. **既定を素直な訳にする**
   いまは公表向けが主。素直な訳を作る前に決めたもので、位置づけが合っていない。

2. **公表向けにコーパスの文例を渡し、根拠を出す**
   「公表向け」と銘打つ以上、どの英文を参考にしたのかを示さないと看板倒れになる。
   日本語で引けるので手元で完結し、往復は増えない。

3. **推敲の往復**
   Copilot の訳は一発では不十分で、原文と訳文を並べて確認させ、具体的に指示して
   直させる作業が実際に行われている。「なんだ、こんなもんか」で使われなくなるより、
   積極的に推敲を促すほうがよい。
   自由入力のみ。押しボタンは置かない（業界にも前例がなく、根拠を集める手段も
   ローカルアプリには無い）。使ってみて毎回書くものが出てきたら、そのとき足す。

4. **機械的な検査（CAT のみ）**
   市販ツールが長年持っている検査のうち、判断が入らないものから入れる。
   - 同じ原文なのに訳が違う ← 課題2そのもの。文字列の一致だけで判定できる
   - 訳文が原文と同じ（訳し忘れ）
   - 長さ（前期の英訳が「実際に収まった長さ」の実測値になる）
   用語集の適用漏れは判断が入る（言い換えを誤検出する）ので保留。

### 第2段階 — 数値の扱いの作り直し

**単位の変換がマスクの段階で走っている。**`122億円` はプロンプトへ渡る前に
`122 oku` になっており、

- 素直な訳にも `oku` が出る（社内の約束を持ち込まない設計に反する）
- 公表向けは `122 oku → ¥12.2 billion` の桁の換算を Copilot にさせている。
  数値を判断させないためにマスクしているのに、換算だけ判断させている

**復元のときに表記ごとに書き分ける**のが筋である。復元は手元の計算なので間違えない。

ただしプロンプトには `[[N1]] oku` という形を前提にした規則が多数あり、単位を伏せると
それらが成り立たなくなる。マスクの設計そのものに手が入るので、数値を壊さないよう
腰を据えて行う。

### 第3段階 — 残っている実務

- **アライメントの完遂**（残り5冊：通期短信1・統合報告書2・有報2）
  段分けを入れた抽出で流し直す。Copilot の制限に当たるので、途中まで保存して
  続きから再開する仕組みは実装済み
- **ECM の実機検証**（連休明け）。書き戻し、図形・テキストボックス、
  行・列の増減への耐性
- **実機での画面確認**。構文検査と回帰テストを通っていても壊れているものが、
  今日3件見つかった

## 未解決の問題

- **Copilot の利用制限** — 121回ほどの連続使用で応答しなくなり、時間を置くまで
  戻らない。Edge を作り直しても回復しない。アプリ側の問題ではない
- **Edge の凍結** — 18分のアイドル後にページ層だけが応答しなくなる事象。
  再現条件を掴めていない。外部から CDP を突く方法は使えない（1ページ1クライアント）
- **書き戻しがセル番地だけを見ている** — 取り込み後に行や列を足すと、訳文が
  ずれたセルへ黙って入る。原文の一致を確かめてから書くべき
- **再開すると Blocks が無い** — Excel から取り込んだものを再開すると、
  出力だけが使えない。画面はそれを伝えていない

## 作業の進め方（今日の反省から）

- **悪い結果が出たら、まず自分の道具を疑う。** 今日、原因を根拠なく断定した誤りが
  9回あった。うち5回は利用者の指摘で気づいた。手順は `CLAUDE.md` にある
- **件数を根拠にしない。** 用語はどちらかに統一されるものなので、出現回数は

- **画面は開いて押す。** 構文検査と回帰テストは、未定義の関数呼び出しも、
  クリックが効かない候補ペインも、捨てられる訳文も検出しなかった
- **指標を作ったら、その指標が拾った実物を数件見る。** 「連結疑い60%」を作った
  時点で中身を見ていれば、短信では表を拾っていると分かった
