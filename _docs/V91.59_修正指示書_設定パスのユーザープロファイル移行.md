# YakuLingo V91.59 修正指示書（利用者設定のユーザープロファイル移行）

作成日: 2026-08-03 / ベース: V91.58

本版は**共有フォルダ運用の見直し（ローカル実行方式）**の3件。
翻訳品質契約・プロンプト・用語集は一切変更しない。

- §1: `user_settings.json` の保存先をアプリフォルダからユーザープロファイルへ移す
- §2: 配布パッケージに `manifest.json`（全ファイルのサイズとSHA-256）を生成する
- §3: 共有フォルダからローカルへ複製して起動する `bootstrap.ps1` と `.cmd` ランチャー

---

## 背景

`user_settings.json` は `$Root\config\user_settings.json`、すなわち
**アプリ本体（バージョンフォルダ）の中**に書き込まれていた。共有フォルダ上の
アプリを全利用者が直接実行する現行運用では、これが3つの問題を生む。

1. **全利用者が1つの設定ファイルを共有する。** 誰かが設定を変更すると全員に及ぶ。
   同時保存が競合する余地もある。
2. **バージョンを更新すると設定が失われる。** 新しいバージョンフォルダには
   `user_settings.json` が存在しないため、既定値に戻る。
3. **共有フォルダを読取専用にできない。** アプリが自分自身のフォルダへ
   書き込むため、誤削除・誤編集に対する保護をかけられない。

さらに、不正JSON時のバックアップ `user_settings.json.invalid-*.bak` も
共有フォルダ上に堆積する。

将来「アプリ本体をローカルへコピーして実行し、共有フォルダは配布元に徹する」
方式へ移行する場合、この状態のままではバージョン更新のたびに全利用者の設定が
消える。したがって配布方式の変更に**先立って**保存先を分離する必要がある。

出力・ログ・診断・履歴は既に `%USERPROFILE%\.yakulingo-ps` 配下にあり
（`Get-YakuDataDir`）、設定だけが例外的にアプリフォルダに残っていた。

## §1 保存先の移行

### 変更点

**src/Paths.ps1**

- `Get-YakuDataDir`: 環境変数 `YAKULINGO_DATA_DIR` による退避先指定を追加する。
  回帰テストが実利用者のデータを汚さずに実行するための口であり、未設定時の
  挙動（`%USERPROFILE%\.yakulingo-ps`）は従来どおりとする。
- `Get-YakuUserSettingsPath` を追加する。
  `%USERPROFILE%\.yakulingo-ps\config\user_settings.json` を返す。
- `Get-YakuLegacyUserSettingsPath -Root` を追加する。
  旧保存先 `$Root\config\user_settings.json` を返す。

**src/Settings.ps1**

- `Resolve-YakuUserSettingsPath -Root` を追加する。
  新パスが存在すればそれを返す。存在せず旧パスが存在する場合のみ、
  旧ファイルを新パスへ**複製**してから新パスを返す。
- `Read-YakuSettings`: 読込先を `Resolve-YakuUserSettingsPath` 経由にする。
- `Read-YakuUserSettingsStrict` / `Save-YakuUserSettings`: 保存・読み戻し先を
  `Get-YakuUserSettingsPath` にする。

### 引き継ぎの原則（重要）

- 旧ファイルは**書き換えない・削除しない**。共有フォルダが読取専用の場合と、
  旧バージョンを使い続ける利用者がいる場合の双方を壊さないため。
- 引き継ぎは**1回だけ**。新パスが出来た後は旧ファイルを二度と参照しない。
- 複製に失敗しても翻訳経路に新たなthrowを持ち込まない。警告ログを残し、
  既定値で継続する（V91.42の原則を踏襲）。

### 既存の移行処理との関係

`Read-YakuSettings` 内の既存レガシー移行（`max_chars_per_batch` 1000→3000、
`edge_debug_port` 9333→9433、`full_text_diagnostics_enabled`→`diagnostics_level`）は
**引き継ぎ後の新パスに対して**適用され、書き戻し先も新パスとなる。
旧ファイルの内容は変化しない。

## 受容基準

1. 設定の保存先が `%USERPROFILE%\.yakulingo-ps\config\user_settings.json` であること。
2. アプリフォルダ配下に `user_settings*` が一切作られないこと。
3. 旧設定を持つ利用者が、値を保ったまま新パスへ移行できること。
4. 引き継ぎ後に旧ファイルを書き換えた場合でも、新パスの値が優先されること。
5. データディレクトリが異なる利用者どうしで設定が独立すること。
6. 旧ファイルが書き換えられず、削除もされないこと。
7. 既存の `Smoke-Test.ps1` 設定ブロックが引き続き通ること。

## 対象外

- プロンプト、用語集、`extractText`、翻訳品質契約。
- 配布方式そのものの変更（ローカルコピー実行・manifest 方式）。本版はその前提整備に留める。
- `settings.template.json` の配置。これは配布物であり、アプリフォルダのまま。

## §2 配布パッケージのマニフェスト生成

### 背景

将来の配布方式では、アプリ本体を共有フォルダからローカルへ複製して実行する。
このとき**複製が完全であることを起動前に確認できなければならない**。
中途半端に複製されたローカル版で起動すると、`Test-YakuUtf8BomForStartup` や
`Assert-YakuBuildIdentity` が原因の分かりにくいエラーを出して停止する。

現行の `Test-YakuPackage.ps1` はZIP内のBOMとファイル名エスケープを検査するが、
**ファイルの中身が正しいかは検査していない**。複製の完全性を検証する土台がない。

### 変更点

**tools/New-YakuPackage.ps1**

- パッケージ直下（`app/` と同じ階層）に `manifest.json` を生成する。

  ```json
  {
    "schema": 1,
    "version": "V91.59",
    "build_id": "V91.59",
    "generated_at": "2026-08-03T...Z",
    "file_count": 58,
    "total_bytes": 1368483,
    "files": [ { "path": "app/config/build.txt", "size": 11, "sha256": "..." } ]
  }
  ```

- `files` の並びは生成環境に依存しないよう**相対パスの序数順**に固定する。
  区切りは `/` に正規化する。`manifest.json` 自身は一覧に含めない。
- 配布物に `user_settings*`、`*.bak`、`*.tmp`、`~$*` が含まれる場合は
  `PACKAGE_FORBIDDEN_FILE` で停止する。§1の引き継ぎ機構により、開発端末の
  `user_settings.json` を同梱すると全利用者の初回起動でそれが取り込まれるため。

**tools/Test-YakuPackage.ps1**

既存の検査（BOM・名前エスケープ・build.txt）に加えて次を検証する。

- `manifest.json` の存在と解析可能性
- `manifest.build_id` / `manifest.version` と `app/config/build.txt` の一致
- 一覧の各ファイルがZIP内に存在し、**サイズとSHA-256が一致**すること
- ZIP内のファイルに**manifest未記載のものがない**こと
- `file_count` と `files` の件数の一致
- `user_settings*` / `*.bak` / `*.tmp` が含まれないこと

### 受容基準

1. `New-YakuPackage.ps1` が manifest 付きZIPを生成し、`Test-YakuPackage.ps1` が通ること。
2. 同一ツリーから2回生成したとき、`generated_at` を除き manifest が完全一致すること。
3. ZIP内のファイルを1バイト改ざんすると `PACKAGE_MANIFEST_HASH_MISMATCH` で落ちること。
4. manifest未記載のファイルを追加すると `PACKAGE_MANIFEST_UNLISTED` で落ちること。
5. manifest を削除すると `PACKAGE_MANIFEST_MISSING` で落ちること。
6. `user_settings.json` を含むツリーは `PACKAGE_FORBIDDEN_FILE` で packaging できないこと。
7. `build.txt` と manifest の build ID が食い違うと `PACKAGE_MANIFEST_BUILD_MISMATCH` で落ちること。

### 対象外

- `bootstrap.ps1` とローカル複製の実装。本版は manifest の**生成と検証**までとする。
- 共有ルートのバージョンポインタ。引き続き `current.txt` を使う。
  manifest はバージョンフォルダ内に置き、そのバージョン自身を記述する。

## §3 ローカル複製起動（bootstrap）

### 背景

アプリは起動時だけでなく**セッション中ずっと共有フォルダを読む**。

| 場面 | 参照先 | 該当箇所 |
| --- | --- | --- |
| 画面表示のたび | `www/index.html`、`www/assets/*` | Server.ps1:1605,1618 |
| 翻訳のたび | `prompts/*.txt`、`glossary.csv`、`prompt_glossary.csv` | PromptBuilder.ps1:69,79,133,138 |
| ファイル翻訳ジョブごと | `src/FileWorker.ps1` を別プロセス起動 | Server.ps1:968-973 |
| Copilot準備・停止 | `tools/Prepare-Copilot.ps1`、`src/ProcessStopper.ps1` を別プロセス起動 | Server.ps1:201-210, 902-915 |
| 上記の各所 | `config/build.txt` を再照合 | Runtime.ps1:37-56 |

そのため実行中にバージョンフォルダを差し替えると `BUILD_ID_DISK_MISMATCH` で
即死する。N-1保持はこの制約下での妥当な対処だったが、制約そのものを外す。

### 変更点

**bootstrap.ps1（共有ルート・新規）**

1. `current.txt` から対象バージョンを決める。不正・不在なら最新のバージョンフォルダへ退避する。
2. `manifest.json` を読み、`<build_id>-<manifestハッシュ8桁>` をローカルの配置先名にする。
3. 導入済みで `.installed` の manifest ハッシュが一致すれば複製しない。
4. 未導入なら `<配置先>.stage-xxxxxxxx` へ複製し、**manifestで全ファイルのサイズと
   SHA-256を照合**し、`.installed` を書いてから**リネームで公開**する。
5. Mark-of-the-Web を外す（`Unblock-File`。Windows以外では何もしない）。
6. 使用中でない古いローカル版を掃除する（リネームできたものだけ削除）。
7. `<配置先>\app\Start-YakuLingo.ps1` を起動する。

**設計上の要点**

- 配置先名に manifest ハッシュを含めるため、**同じバージョン名で中身が変わっても
  別フォルダ**になる。使用中のローカル版を上書きする経路が存在しない。
- 公開は必ずリネーム。中途半端な複製が起動対象になることはない。
- 導入時の失敗ではステージングフォルダを消し、何も残さない。
- 共有フォルダへ到達できない場合は導入済みのローカル版で起動する（オフライン継続）。
- `manifest.json` を持たない旧パッケージへロールバックした場合は、従来どおり
  共有フォルダ上で直接起動する（互換動作）。

**YakuLingo起動.cmd（共有ルート・新規）**

- `bootstrap.ps1` をローカル一時パスへ複製してから実行する。共有フォルダを
  セッション中掴み続けないため。
- 内容はASCIIのみ。cmd.exeはコンソールのコードページで読むため、日本語を書くと
  環境によって文字化けする。

**YakuLingo起動.vbs（共有ルート）**

- VBScriptはMicrosoftが廃止予定（機能デマンド化→将来削除）のため、`.cmd` へ
  転送するだけの互換シムにする。既存ショートカットを壊さないために残す。

**その他**

- バージョンフォルダにも保守用の `YakuLingo起動.cmd`（その場で直接起動）を追加する。
- `Create-Desktop-Shortcut.ps1` は共有ルートの `.cmd` を指す。作業フォルダは
  ローカルパスにする（共有フォルダにすると cmd.exe が UNC の警告を出すため）。
- `New-YakuPackage.ps1` は隠しファイルも列挙し（`-Force`）、ZIPを `Compress-Archive`
  ではなく manifest の一覧から直接組み立てる。`Compress-Archive` は隠しファイルの
  扱いがプラットフォームで異なり、ZIPとmanifestが食い違うため。

### 受容基準

1. 初回起動でローカルへ導入され、起動対象が共有フォルダ配下でないこと。
2. 2回目以降は再複製しないこと。
3. 共有側の内容が変わると別フォルダへ導入し、使用中でない旧ローカル版を掃除すること。
4. 共有へ到達できないとき、導入済みローカル版で起動すること。共有もローカルも
   無ければ `SHARED_VERSION_NOT_FOUND` で停止すること。
5. 共有パッケージが1バイトでも改ざんされていれば `INSTALL_VERIFY_FAILED` で
   導入を中止し、中途半端なフォルダを残さないこと。
6. `manifest.json` の無い旧版では共有フォルダ上で直接起動すること。
7. `current.txt` が不正でも実在する版で起動すること。

### 対象外

- 実行中の利用者への更新通知。反映は次回起動時とし、強制終了はしない。
- 共有フォルダのレイアウト変更。`current.txt` によるポインタ方式を継続する。
