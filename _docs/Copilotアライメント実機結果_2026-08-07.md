# Copilot による日英アライメント 実機結果

2026-08-07

## 結論

50行ずつに割って Copilot へ渡す方式で、実文書の網羅率 99% を得た。
同じ文書を1回で投げたときは 75% だったので、分割が効いている。

## 測定

有価証券報告書 R&D 節（liteparse plain text 抽出、日100行 / 英120行）

```
対 41組 / Copilot 呼び出し 5回 / 割り直し 1回 / 52秒
網羅  日 99%（拾えなかったのは J95 の1行）  英 84%
数値の裏取り  対象8組 / 一致8組
数値の食い違いで外した対  0組
```

比較（同じ節、同じ抽出）

| 渡し方 | 日本語の網羅 |
| --- | --- |
| 100行を1回で | 75%（J65〜J91 が連続脱落） |
| 50行ずつ2回 + 割り直し | 99% |

英語の網羅が 84% にとどまるのは、英語側に日本語へ対応しない行（見出しの
繰り返し、図表のキャプション）が含まれるため。対訳として使えない行なので
拾えないのは正しい。

## 送信内容

数値は全てマスクして送っている。社内ルール（未公開の財務情報は数字だけ
マスクする）に従う。マスクによる精度低下は無い——同じ節で数値ありと
数値マスクを比べ、21組すべてが完全に一致した。

裏取りは手元の原文で行う。Copilot からは行番号しか返らないので、
番号を引き直せば数値を見せずに数値で照合できる。

## 実機で起きた不具合

18分間アイドルにしたあと、Copilot 用 Edge が半死状態になった。

```
11:37  正常に応答（マスク版の試験が成功）
       ── 18分間、記録なし ──
11:55  Runtime.evaluate が15秒タイムアウト。以後、再試行しても同じ
```

観測できたこと

- ブラウザ層（`/json/list`）は即答する
- ページ層（`Runtime.evaluate`）はどのページも応答しない
- 別プロセスから WebSocket を開こうとしても繋がらない
- 他アプリとの競合ではない。ポートもプロファイルも分かれている
  （YakuLingo 9433 / .yakulingo-ps、PdfKoseiAssist 9444 / .pdf-kosei-ps、
  ManualBuilder は自前の copilot-edge-profile）

有力な仮説は Edge のスリープタブ。アイドル後に renderer が凍結され、
CDP のページ層だけが応答しなくなる、という筋は観測と矛盾しない。
ただし**まだ確かめていない**。再現条件を掴む前に自動再起動を入れると、
別の理由で固まったときに作り直しを繰り返す危険がある。

現在のエラーメッセージは「アンケート等のダイアログを閉じてください」だが、
今回ダイアログは無かった。原因と違うことを告げるので、調査を誤らせる。
ここは先に直すべき。

## この日の反省

原因を3回、根拠なく断定した。

- 「画面で何かを待っている」→ 待っていなかった
- 「他のアプリが掴んでいる」→ ポートもプロファイルも分かれていた
- 「4割の対応が誤り」→ 自分の照合が単位換算を見ていなかった

いずれもログとプロセスを見れば分かることだった。
数字や症状が悪いとき、まず自分の道具を疑う。
