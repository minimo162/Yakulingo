# 欠陥記録: パレット文脈ポインタの残課題 (2026-08-19)

文脈ポインタ(パレットの「この資料の確定訳」)のCoD審査・第2ラウンドで確認された、
**修正せずに記録へ残す**項目。いずれもレビュー役が実測・再現済み。修正済みの指摘
(点検鮮度ガード、保存文脈の表示名喪失など)はコミット履歴にあり、ここには書かない。

## 1. 用語ストアの読み方が同じ応答の中で食い違う(fail-safe だが不整合)

`/api/palette/instant` の context 経路は、同じ用語ストアを2回・別の厳密さで読む。

- 鮮度ハッシュ: `Get-YakuCatTerminologySnapshotHash` → `Get-YakuCatTerminologyEntries`
  (`src/CatProject.ps1:72-74`) が **`-Strict`** で読み、壊れた行が1行でもあると
  `TERMINOLOGY_STORE_INVALID_JSON` を投げる(ルート側で握って project_hit=null)。
- 用語一致: そのすぐ下(`src/Server.ps1` の terms ブロック)は **`-Strict` なし**で読み、
  壊れた行だけ飛ばして続行する。

ストアは追記専用 JSONL なので、書き込み途中のクラッシュやディスク満杯で
「末尾1行だけ壊れる」形が実際に起こる。実測: `personal-v2.jsonl` の末尾に
`{"term_id":"broken","ver` を追記 → `hit=False / terms=1`。**文脈ヒットだけ死に、
用語は生き残る。** データ喪失も 500 も無いが、直すなら読みを1回に共通化して
非 Strict に揃える(下記 2 とまとめて1変更)。

## 2. 貼り付けごとに用語ストアを2回読む(実測 +0.67ms/エントリ)

同じ ProjectId で、鮮度ハッシュ用と一致検索用に2回パースする。直列リスナーなので
Copilot ジョブ開始の手前に足される。

    terms=0    +5.2ms / terms=100  +50.7ms / terms=400  +268.1ms

読みを1回共有すれば消える。1 の修正と同一変更で済む。

## 3. segment_count の無い manifest は復元が永久に省略される

`Get-YakuCatProjectDiskSegmentCount` (`src/CatProject.ps1:2512-2513` 付近)は
manifest に `segment_count` が無いと `$null` を返し、呼び出し側は復元を省略する。
レガシー配置 `store/<id>.json`(関数自身が意図的に対応しており、
`Restore-YakuCatProject` は今も復元できる)がこれに該当する。
実測: 400行のレガシー記録 → NULL → **復元が一度も走らない**(文脈ヒットが黙って出ない)。
レガシー記録はセグメントを本体に抱えているので `@($manifest.segments).Count` が
無料のフォールバックになる。

## 4. 兄弟関数 `Get-YakuCatProjectDiskRevision` のパス区切り決め打ち(既存)

`src/CatProject.ps1:2475,2477` が `'\'` を決め打ちしており、非 Windows では常に
`$null`。今回 `Get-YakuCatProjectDiskSegmentCount` 側は
`[System.IO.Path]::DirectorySeparatorChar` へ直したが、兄弟は未修正
(本番は Windows なので実害なし)。呼び出し元は 409 応答の `current_revision` 1箇所のみ、
試験からの呼び出しは無い。**直した関数の2行上に同じバグが残っている**ので、
次にこの周辺を触るときに同じ2文字修正を入れること。コピー元に選ばないこと。

## 5. 判定記録: 300セグメント超の資料は復元を省略する(v1 の割り切り)

`src/Server.ps1:2589-2597` の閾値(定数・調整可)。実測: 320セグで省略・11ms、
40セグで復元・501ms。仕様の絶対制約(409/500 にしない・翻訳は続く)は満たすが、
**本命の資料クラス(決算説明会資料は300セグを軽く超える)では、CATがその資料を
開いているときしか文脈ヒットが出ない**。選択UIは選ばれたままなので、出ない理由は
画面に現れない。レビュー役の判定は「v1 として許容、ただし最弱部。1回きりの
~1-2秒の停止を受けるか、非同期復元が望ましい」。閾値を上げる/非同期化する場合は
V9203 の MINOR-4 系 assert(両側の境界)を併せて更新する。

## 6. 試験の脆さ(赤が出たときに製品欠陥と誤読しないための注記)

- V9203 の幾何 assert は `115.9px`(480x640・選択肢4件)の**厳密一致**。Chromium や
  フォントの更新で赤に変わり得る。本来の不変条件は「折り返し行が増えない・入力欄が
  見える」なので、赤になったらまず実測し、行数 assert へ書き換えるのが正しい対処。
- Server.ps1 への静的文字列 assert(`-Segment \$seg -TerminologySnapshotHash ...`)は
  変数名 `$seg` の改名で赤になる。挙動 assert の重複保険であり、単体の赤は改名を疑う。
