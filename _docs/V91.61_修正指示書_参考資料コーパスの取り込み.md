# V91.61 修正指示書: 参考資料コーパスの取り込み（PDF → Markdown）

作成日: 2026-08-04 / 対象: V91.60 / 段階: **1**
（`要件整理_汎用翻訳アプリとRAG翻訳.md` §13-8 の段階1）

## この版の位置づけ

**参考資料フォルダに置かれた PDF を Markdown へ変換して保存する経路だけを作る。**

- **検索も文例注入も行わない。** 段階2以降。
- **翻訳の挙動を変えない。** プロンプト・用語集・翻訳経路に触れない。
- 参考資料フォルダが未設定・到達不能なら、アプリは V91.60 と完全に同じ動作をする。

### なぜ取り込みだけを切り出すか

取り込みが正しく動くことは、検索の良し悪しとは独立に確かめられる。
一緒に入れると、訳質が変わらなかったときに「検索が悪いのか、取り込みが悪いのか」を
切り分けられない。**先に、確かめられるほうを確かめる。**

## §2 フォルダ構成

### §2-1 参考資料フォルダ（共有）

```
参考資料フォルダ（corpus_root。財務本部限定の共有フォルダ）
  ├─ 英文短信/                          ← 利用者が PDF を置く
  │     2027-1Q_tanshin_en.pdf
  │     2026-4Q_tanshin_en.pdf
  ├─ 英文アニュアルレポート/
  │     AR2026_en.pdf
  └─ _corpus/                           ← アプリが作る。利用者は触らない
        manifest.json                   ← 取り込み済みの一覧
        英文短信/2027-1Q_tanshin_en.md
        英文アニュアルレポート/AR2026_en.md
```

- **直下のフォルダ1つ＝1データベース**とする。利用者が段階2以降で選ぶ単位になる。
- `_corpus/` は元の階層を保つ。出典をたどれるようにするため。
- **利用者がすることは「フォルダに PDF を置く」だけ。**

### §2-2 ローカル複製実行との関係（重要）

**このアプリは共有フォルダから起動するが、本体はローカルへ複製されてから動く**
（V91.59 の `bootstrap.ps1`）。実行時の `$script:YakuRoot` は
`%LOCALAPPDATA%\YakuLingo\versions\<build>-<hash>\app` を指す。

これを踏まえて3点を決める。

#### (1) WASM の配置 — 影響なし

`app/www/vendor/liteparse/` は配布物の一部なので**ローカル複製と一緒に来る。**
共有フォルダを読みに行かないため、読み込みは速く、共有が落ちていても動く。
`bootstrap.ps1` の SHA-256 検証にもそのまま乗る。**特別な対応は要らない。**

#### (2) 取込結果の保管先 — 共有とローカルの二段にする

当初「`_corpus/` を共有フォルダへ置き、誰か1人が取り込めば全員が使える」とだけ書いたが、
**配布用の共有フォルダは一般利用者にとって読み取り専用である可能性が高い**
（`New-YakuUploadFolder.ps1` が示すとおり、公開は管理者が行う運用）。
読み取り専用だと一般利用者は取り込めない。

**共有への書き込み可否で分岐せず、二段構えにする。**

| 段 | 場所 | 書き手 | 読み手 |
| --- | --- | --- | --- |
| 共有 | `<corpus_root>/_corpus/` | 書ける人（管理者など） | 全員 |
| ローカル | `<データディレクトリ>/corpus/` | **本人** | 本人 |

- 読むときは**共有を先に見て、ローカルで補う。** 同じ `id` があれば共有を優先する
- 取り込むとき、共有へ書けるなら共有へ、書けなければローカルへ保存する
- **書き込み可否は試して判定する。** 事前に権限を調べない（共有フォルダでは当てにならない）

これで次が両立する。

- 管理者が一度取り込めば、全員が何もせずに使える
- 権限が無い利用者も、自分の手元で使える（**機能縮退。失敗にしない**）

#### (3) ローカル側は版更新を跨いで残す

**`%LOCALAPPDATA%\YakuLingo\versions\<build>-<hash>\` の下へ置いてはいけない。**
このフォルダは版ごとに作られ、更新のたびに別フォルダになる。
取込結果を置くと**版を上げるたびに全部やり直しになる。**

V91.59 が利用者設定に対して行った判断と同じ扱いにする。

```powershell
Get-YakuSubDir 'corpus'      # = <データディレクトリ>/corpus
                             #   既定 %USERPROFILE%\.yakulingo-ps\corpus
                             #   YAKULINGO_DATA_DIR で退避できる（回帰テスト用）
```

`Get-YakuDataDir` はユーザープロファイル配下であり、版更新でも消えない。
`YAKULINGO_DATA_DIR` を尊重するため、回帰テストが実データを汚さずに走る。

#### ローカルへ置くことの機密上の扱い

ローカル側の `corpus/` には、共有と同じ内容（マスキング済み・英語のみ）が入る。
**利用者は財務本部の構成員であり、元の資料そのものを扱える立場にある。**
手元に写しが残ることは新しい露出にならない。

ただし段階5で過去 ECM 英訳を入れる際は、**マスキング前の原文を
ローカルへ書かない**こと（マスクは取り込み時に済ませる。要件整理 §6-4）。

#### 段階2への申し送り

検索のたびに共有フォルダの `.md` を読むと遅い。
**段階2では索引をローカル（`corpus/index/`）へ作り、共有の manifest の版で
古さを判定する。** `bootstrap.ps1` がアプリ本体に対して行っているのと同じ形にする。
この版では索引を作らないため、置き場所だけ決めておく。

## §3 取り込みの流れ

```
① 設定で参考資料フォルダを指定する（既定は空 = 機能ごと無効）
② アプリが *.pdf を列挙し、_corpus/manifest.json と突き合わせて未取込を出す
③ 利用者が「取り込む」を押す
④ ブラウザが1件ずつ処理する
     GET  /api/corpus/pdf?id=...     PDF のバイト列を受け取る
     WASM で解析（ocrEnabled:false, outputFormat:'markdown'）
     POST /api/corpus/ingest         Markdown を返す
⑤ サーバーが _corpus/ へ .md を保存し、manifest.json を更新する
```

**ブラウザにフォルダを読ませない。** ブラウザ単体ではフォルダを列挙できないため、
**列挙・読み出し・保存はすべて PowerShell が行い、ブラウザは解析だけを担う。**
これで決定事項#1（フォルダ指定）が成立する。

## §4 実装

### §4-1 WASM の同梱

| 配置 | 内容 |
| --- | --- |
| `app/www/vendor/liteparse/liteparse_wasm.js` | 37 KB |
| `app/www/vendor/liteparse/liteparse_wasm_bg.wasm` | 5.3 MB |
| `app/www/vendor/liteparse/LICENSE` | Apache-2.0 の写し |

- `New-YakuPackage.ps1` の manifest と SHA-256 検証にそのまま乗る。特別扱いしない。
- `.d.ts` は同梱しない（型定義は実行に不要）。

**`Get-YakuMimeType`（`Server.ps1:1489`）へ `.wasm` を追加する。**

```powershell
'.wasm' { 'application/wasm' }
```

`WebAssembly.instantiateStreaming` が正しい MIME を要求するため。
配信できない環境向けに、JS 側は `ArrayBuffer` 経由の初期化へ落とせるようにしておく。

### §4-2 設定

`Get-YakuSettingsSchema`（`Settings.ps1:85`）へ1件追加する。

```powershell
corpus_root = @{ Type='string'; Default=''; MaxLength=260 }
```

- **既定は空。空なら参考資料の機能は一切動かない**（V91.60 と同じ動作）。
- **保存時に存在確認をしない。** 共有フォルダは一時的に到達不能になる。
  到達性は使うときに判定し、失敗しても保存済みの設定は消さない。

### §4-3 サーバー API

| メソッド | パス | 役割 |
| --- | --- | --- |
| GET | `/api/corpus/status` | フォルダの到達性、データベース一覧、取込済/未取込の件数 |
| GET | `/api/corpus/pending` | 未取込 PDF の一覧（id・相対パス・サイズ） |
| GET | `/api/corpus/pdf?id=...` | PDF のバイト列。**id は manifest 由来のものだけを受け付ける** |
| POST | `/api/corpus/ingest` | `{id, markdown, pages, chars}` を受け取り保存 |

**`corpus_root` 配下から出ないことを、`Serve-YakuStaticFile` と同じ方式で検査する**
（`GetFullPath` して基準パスの前方一致を確認）。
`id` にパスそのものを使わず、manifest の索引経由にするのは、
利用者の入力が直接ファイルパスにならないようにするためである。

### §4-4 manifest.json

```json
{
  "schema": "yaku-corpus-1",
  "updated": "2026-08-04T12:00:00",
  "entries": [
    {
      "id": "a1b2c3d4",
      "database": "英文短信",
      "source": "英文短信/2027-1Q_tanshin_en.pdf",
      "sha256": "…",
      "markdown": "_corpus/英文短信/2027-1Q_tanshin_en.md",
      "pages": 15,
      "chars": 30821,
      "status": "ok",
      "note": ""
    }
  ]
}
```

- `id` は `sha256` の先頭8桁。**同じ内容の PDF は名前が違っても同じ id になる。**
- `status` は `ok` / `low-text` / `failed`。
- 書き込みは `Write-YakuTextAtomic`（既存）を使う。
- **共有側とローカル側で同じ形式にする。** 読むときは両方を読み、`id` が重なれば共有を採る。

### §4-5 保存する Markdown

WASM が返すページごとの markdown を、**ページ境界のコメントを挟んで連結する。**

```markdown
<!--yaku-page:1-->
Consolidated Financial Results ...

<!--yaku-page:2-->
...
```

段階2以降で「どの資料の何ページから引いたか」を示せるようにするため。
本文には手を加えない。

## §5 落とし穴として先に潰しておくこと

### §5-1 OCR を起動させない

`ocrEnabled: false` を必ず渡す。**渡し忘れると tessdata を GitHub から取りに行き、
社内網では失敗して取り込みが止まる**（要件整理 §13-1 で実測）。

`isComplex()` は**使わない。** 15ページ中10ページで `needsOcr=true` が立つのに、
OCR なしで全ページからテキストが取れた（同 §13-6）。信号として役に立たない。

### §5-2 抽出量が少ない資料を見分ける

ページあたりの抽出文字数が閾値（既定 200字）を下回るページが半数を超えたら、
`status: low-text` として記録し、画面に出す。
**エラーにはしない。** 画像主体の資料は正常に「取れない」だけである。

### §5-3 同時実行 — ロックではなく冪等で解く

共有フォルダなので複数人が同時に取り込みうる。**ロックを取らない設計にする。**

- `.md` はファイル単位で独立している。同じ内容が2回書かれても結果は同じ
- `manifest.json` は読み → 統合 → アトミック書き換え。
  **書き込み直前に読み直し、他者の追加分を取り込んでから書く**
- 同じ PDF を2人が取り込んでも、`id` が sha256 由来なので同一エントリに収束する

`Local\` 名前空間の Mutex はマシン内でしか効かないため、共有フォルダの排他には使えない。
**衝突しても壊れないほうが、排他するより単純で堅い。**

### §5-4 到達不能時にアプリを止めない

`corpus_root` が未設定・存在しない・権限がない場合:

- 参考資料パネルに理由を出す
- **翻訳機能は通常どおり動く**（要件整理 §6-4 の機能縮退の方針）
- 起動を遅らせない。到達性の確認はパネルを開いたときに行う
- **ローカルに取込済みのものがあれば、それは使えるままにする。**
  共有が落ちていても、手元の分だけで段階2以降が動く

### §5-5 起動を遅くしない

**起動時に取り込みを走らせない。** 利用者が明示的に押したときだけ動かす。
WASM の初期化（実測 369ms）も、参考資料パネルを開いたときに初めて行う。

`www/index.html` の補助パネル（履歴・用語集・設定）へ**「参考資料」を追加**する。

```
参考資料（翻訳の文例に使います）
  フォルダ: \\...\財務本部\ECM資料英訳ツール\参考資料      [変更]
```

  パネルに「文例としての利用は次版から有効になります」と明記する。

## §8 受容基準

1. `corpus_root` が未設定のとき、アプリの挙動が V91.60 と**バイト単位で同じ**であること
   （プロンプト・翻訳経路に差分がないこと）
2. `.wasm` が `Content-Type: application/wasm` で配信されること
3. 15ページの PDF が **1秒以内**に取り込めること（実測値 692ms + 通信）
4. 取り込み中に**外部への通信が発生しない**こと（開発者ツールのネットワークで確認）
5. **OCR を起動しない**こと（tessdata を取りに行かない）
6. 同じ PDF を2回取り込んでも manifest のエントリが増えないこと（冪等）
7. 別名で保存した同一内容の PDF が、同じ `id` に収束すること
8. 2つのアプリから同時に取り込んでも `manifest.json` が壊れず、両方の結果が残ること
9. 壊れた PDF で停止せず、`status: failed` を記録して次へ進むこと
10. 画像主体の PDF が `status: low-text` になり、画面に出ること
11. `corpus_root` へ到達できないとき、アプリが起動し翻訳できること
12. `corpus_root` の外のパスを `id` に与えても読めないこと
13. 配布物が 5.2MB 増え、`Test-YakuPackage.ps1` が通ること
14. **共有フォルダが読み取り専用でも取り込めること**（ローカルへ保存される）
15. **共有とローカルの両方に取込結果があるとき、共有が優先されること**
16. **版を上げてもローカルの取込結果が残ること**（`versions/<build>-<hash>/` の下に置かない）
17. `YAKULINGO_DATA_DIR` を設定したとき、取込結果がその配下へ行くこと
18. 既存の回帰（Check-Encoding / 数値マスキング / 設定パス / bootstrap / V91.7 / V91.10 / V91.17）が
    すべて通ること
