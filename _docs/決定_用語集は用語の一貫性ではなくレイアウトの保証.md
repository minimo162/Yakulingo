# 決定: ファイル翻訳の用語集は「レイアウトの保証」である

決定 2026-08-05

---

## §1 何が分かったか

**ファイル翻訳の完全一致置換（`cell-exact`）は、実運用では
「用語の一貫性」ではなく「はみ出さないことの保証」として使われている。**

利用者の運用（2026-08-05 の説明）:

> 今は過去のラベルを用語集にして、完全一致で置き換えることで、
> ラベルが変わらない限りはみ出ないようにしています。

過去のラベルは**その列に収まっていたから採用された**訳語である。
同じ訳語を使えば必ず収まる。これは辞書ではなく**寸法の記録**である。

### この見方から出る帰結

| 帰結 | 理由 |
| --- | --- |
| **`cell-exact` は決定的でなければならない** | 「だいたい守られる」ではレイアウトが崩れる。プロンプトへ書いて Copilot に守らせる形では保証にならない |
| **用語集を網羅する必要はない** | 保証が要るのは「はみ出すセル」だけ。全語を書ききろうとするから終わらない |
| **穴は「新しいラベル」** | ラベルが変われば保証が消える。しかも**それが見えない** |

---

## §2 なぜ長さを翻訳側で制御しないのか

短く訳したい理由は**エクセルの印刷範囲に収めるため**であり、
それ以外の手段（フォントサイズ、行の高さ）でも満たせる。
**意味が通らない英語になるくらいなら、レイアウトで調整するほうがよい**（利用者の判断）。

したがって:

| 案 | 判断 |
| --- | --- |
| 字幕方式（数値上限を決め、超過したら再依頼） | **採らない。** 再依頼は時間がかかるうえ、無茶な翻訳になりやすい |
| 上限文字数をセルごとに事前提示する | **保留。** 効果が不確か（IWSLT 2025 も数値予算は未検証）。外すと意味が通らない英語を招く |
| 長い文章のはみ出し | **レイアウトで吸収する。** 翻訳側では手当てしない |
| 短いラベルのはみ出し | **用語集で保証する。** ただし穴（新ラベル）を見えるようにする ← §3 |

BRIEF 規則にある `Length is diagnostic, not a target.`（長さは目安であって目標ではない）は、
この要件に対して**正しい**。長さは制約であって目標ではない。

---

## §3 実装したもの

### §3-1 用語集に無い短いラベルを知らせる

ファイル翻訳の後、**完全一致で置換できなかった短いラベル**を警告として出す。

```
用語集に無いラベル
  用語集に無い短いラベルが 7 件ありました。列幅からはみ出す可能性があります。
  次回以降のために用語集への追加を検討してください: 新規項目A、為替差損益、…
```

- 既存の警告チャンネルに category を1つ足しただけ。**新しい画面も設定も増やしていない**
- **既にあるデータだけで求まる**（項目一覧と `cell-exact` の適用結果の差分）。
  Excel の幅を測る必要も、Copilot への往復を増やす必要もない
- **検出しても再依頼はしない。** 見せるだけである

判定（`Test-YakuFileLabelLike`）:

**長さだけでは足りない。** セルの中の短文は句点を持たないことが多く
（`為替影響により営業利益が減少`）、文字数の上限だけでは拾ってしまう。

| 条件 | 理由 |
| --- | --- |
| 16 文字以内 | 列に収める対象は短い |
| 改行を含まない | 複数行はラベルではない |
| 文末記号・読点（。．！？、，）を含まない | 文はレイアウト（行高）で吸収する領域 |
| **格助詞「を」「が」を含まない** | 文の印。ラベルにはまず現れない |
| **接続表現を含まない**（により / による / に伴い / のため / ものの …） | 同上 |
| **述語で終わらない**（した / します / される / である / ない …） | **末尾だけを見る。** 途中の活用（`親会社株主に帰属する当期純利益` の「帰属する」）は正当なラベルの一部 |
| 日本語を含む | 数字・記号だけは訳す対象が無い。英語だけは JA→EN で訳されない |
| JA→EN のときだけ | 英語のほうが長くなりやすく、はみ出しが問題になるのはその向き |

拾いたいもの: `販売促進費` / `のれん償却` / `販売費及び一般管理費` / `親会社株主に帰属する当期純利益`
拾いたくないもの: `為替影響により営業利益が減少` / `コストを削減` / `出荷台数が増加した`

判定は完全でなくてよい。ここで拾うのは**用語集へ足す候補**であって、
間違って拾っても人が捨てるだけである。逆に取りこぼすと気づけない。
**残った誤りは短い順に並べることで下へ沈む** — 上から見れば用が足りる。

同じ字面は1件にまとめるが、**空白違いは別項目として出す**。
`cell-exact` は正規化した字面で突き合わせるため、用語集にも別々の行が要る。
ここでまとめると、足りない行に気づけない。

### §3-2 コーパス文例は FULL の手本であって BRIEF の手本ではない

段階3 で入れた `CORPUS_EXAMPLES` は**開示資料の通常長の英文**である。
それを BRIEF を求める同じプロンプトへ同居させていた。

IWSLT 2025 の実測（`Prompting LLMs: Length Control for Isometric Machine Translation`）:

- **等長の例文を見せると、モデルは長さの指示を無視する**
- 極端に短い例文を見せたときだけ効いた
- 指示の文言と例文の性質が一致していないと、差は無視できる程度

いまの構成はこの条件に当てはまるため、**文例が BRIEF を薄めていた可能性がある。**
プロンプトへ適用範囲を1行足して名指しした。

```
SCOPE: these excerpts are full-length disclosure prose. They are a model for
FULL_TEXT wording only. They are NOT a model for BRIEF_TEXT: their length and
sentence style say nothing about how short BRIEF must be.
```

BRIEF 規則の中にある `FULL "…" -> BRIEF "…"` の15組は**極端な圧縮例**であり、
研究の言う正しい形になっている。こちらは触らない。

**根本的な解決は FULL と BRIEF を別の依頼に分けること**（要件整理 §5-A）。
分ければ、通常長の文例は FULL の依頼へ、圧縮例は BRIEF の依頼へ入り、
指示と例文の性質が各依頼で揃う。ただしそれは別の決定なので、ここでは但し書きに留める。

## §4 受容基準

1. 用語集に無い短いラベルが**警告として一覧に出る**こと
2. 完全一致で置換できたラベルは出ないこと
3. 文（文末記号を持つもの）・数字だけ・英語だけは出ないこと
4. EN→JA では出ないこと
5. 数値マスク後でも**原文の字面**で出ること（用語集へそのまま写せる形）
6. 同じ字面は1件にまとまり、**空白違いは別項目**として出ること
6a. 句点の無い短文（`為替影響により営業利益が減少`）を拾わないこと
6b. 途中に活用を含む正当なラベル（`親会社株主に帰属する当期純利益`）を落とさないこと
6c. **短い順に並ぶ**こと
7. 検出しても**再依頼しない**こと
8. コーパス文例が **FULL の手本であって BRIEF の手本ではない**と明示されていること
9. 設定項目も画面も増やしていないこと
10. 既存の回帰がすべて通ること

回帰は `app/tools/Test-YakuV9161LabelCoverage.ps1`。

## §5 まだ決めていないこと

| 事項 | 状況 |
| --- | --- |
| はみ出しそのものの検出（列幅とフォントから文字幅を実測） | **保留。** Windows のフォント描画が要るため、いまの検証環境（Linux / PowerShell 7）では確かめられない。ラベル一覧で運用が回るか見てから判断する |
| FULL / BRIEF を別の依頼に分けるか | 実測では、いまのテキスト翻訳プロンプトは 13,826 字でそのうち BRIEF 規則が 7,772 字（56%）。分けても送信量の合計はほぼ同じで、各回の出力は半分になる。**往復2回でも所要時間が倍にはならない見込み** |
| 用語集をプロンプトから外すか | ラベル側（`cell-exact`）は外せない（レイアウトの保証だから）。プロンプトへ渡す分は、コーパスで代替できるか実データで比べてから |
| 長い文章の上限提示 | 保留（§2） |
