## 5-4. 「略語を使うな。承認済みの略語は呼び出し側が後から当てる」について

利用者から「これは私の提案というより、その時のclaudeの主張なのだが」と
指摘があったので、主張のままになっていないか実装で確かめた。

**実装されている。** `src/BriefStyle.ps1` が置換表を持ち、短縮経路を含む
4か所（`Translation.ps1:1715 / 1851 / 1964 / 2052`）で適用している。
理由も書かれている。

> プロンプトに書いても「使え」と言っているだけで、守られるかは確率的である。
> アプリで当てれば**必ず**揃う。用語集が「レイアウトの保証」だったのと同じで、
> **プロンプトの指示は保証にならない。**

**しかも一つずつ根拠が残っている。** 月名は文脈に依らないつもりで載せていたが、
実機で `April Smith -> Apr. Smith` と人名を潰したので**わざとプロンプト側へ
戻して**ある。`revenue -> rev.` は「revised」とも読めるので外してある。
`forecast` `actual` は動詞・形容詞の用法があるので入れていない。

**主張が要件に化けた例ではない。** 判断の要るものはモデル、要らないものは
コード、という切り分けである。

**ただし表のラベルには足りない。** 表は 4/20 しか枠に収まっていない。
置換表は決算の言い回し向けで、見出しの語には `consolidated -> consol.` くらいしか
当たらない（実測で C06 C07 C13 C14 に発火）。利用者の

> 表の項目は文体で短くするのが難しいので、多少無理なabbreviationになっても仕方がない

は、**置換表を大きくする話ではなく、場面で方針を変える話**である。散文では
今の慎重さが正しく、ラベルでは緩めてよい。**別の変更である。**

### 確定表の限界（利用者の指摘 2026-08-17）

> 「プロンプトに書いても守られるかは確率的。アプリで当てれば必ず揃う」というのは
> そうだが、その代わりにあらかじめ用意していないものは生み出されないので、
> 拡張性に劣る。

**そのとおりで、測定がそれを示している。** 置換表は決算の言い回し向けで、
表の見出し20行に当たったのは `consolidated -> consol.` だけだった（4行）。
残る16行は、短くする手段が1つも用意されていない。

そしてこれは利用者の仕事のいちばん要る所で効かない。

> ただ時々新しい項目が追加されるので、そのときは短い訳を提示してあげる必要がある

**新しい項目は、定義上、表に載っていない。**

**したがって「表かモデルか」ではなく、両方が要る。** アプリの原則
（`BriefStyle.ps1` 冒頭）は「指示は保証にならない」であって
「モデルに作らせるな」ではない。保証できるものは表で確定させ、
**表に無いものはモデルに作らせて、門で確かめる**。短縮経路は既に門を持っている
（事実・伏せた数値・固有名詞・行数・実際に短いか）。略語に足すなら、

```

末尾に句点を置く形であること
1回の出力の中で同じ語に同じ略を当てていること
それでも枠に入らないなら、短縮しない版を返す
```

のような機械で確かめられる条件になる。**「多少無理な略語」を許すのは、
無検査で許すことではない。**

これは案であって、まだ測っていない。効果は同じ20行で測れる（いまの 4/20）。
