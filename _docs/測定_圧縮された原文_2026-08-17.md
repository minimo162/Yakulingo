## 2. 物差しが逆を向くとはどういうことか

**公表英文自身が枠に収まるのは 20行中5行しかない。**

```
年間配当金（5字, 枠10字）           -> Dividends Per Share（19字）
四半期連結損益計算書（10字, 枠20字） -> Quarterly Consolidated Statements of Operations（47字）
41 DX／AXの取り組み（13字, 枠24字）  -> 41 Digital Transformation and AI Transformation Initiatives（59字）
```

紙面には横幅の自由があったので、公表訳は縮めていない。だから
**「公表訳に近いほど良い」を圧縮された原文に当てると、枠に収まる訳ほど点が下がる。**
Nani（0.702）は公表訳に近いが収まらず、幅を伝えたLLM（0.575）は収まるが遠い。
**散文の比較で YakuLingo を並べた尺度は、この題材では優劣の判定に使えない。**

**セルに収まるかの判定には、利用者の実ファイルの実際の列幅が要る。**
それが無いまま私が幅を決めれば、`@media (max-width: 1400px)` を踏ませたくて
1380px を選び、それを「実機」と呼んで2倍外したのと同じことになる。

## 3. 「幅を伝えられる」こと自体が道具の差である

上の表の2行は、モデルの優劣ではない。**幅を伝えたか伝えなかったかの差**である。
Nani と DeepL には、1回の翻訳に対して幅の条件を渡す場所が無い。
YakuLingo にはある（電文体の翻訳と「情報を保って短くする候補」＝`cat.html:484`、
`prompts/text_translate_brief_to_en.txt`、`text_shorten_to_en.txt`）。

**同じモデルに幅の指示だけを外した対照を走らせて、モデル差と指示差を分けた**
（§6 に結果）。

## 4. 数字は多く残せばよいわけではない

公表訳が 14/16 と出たので、参照訳が正解のはずだと考えて2件を追った。
**2件とも公表訳が正しく、私の照合が間違っていた。**

```
C02  ５月 初のロータリーエンジン搭載車…   -> Introduced Mazda Cosmo Sports (110S), ...
     「５月」は年表の別の列にある月ラベルで、対訳を作るときに紛れ込んだもの。
     訳文に月が無いのは正しい（題材側の欠陥）
C15  潜在株式調整後１株当たり当期純利益   -> Diluted net income per share of common stock
     「１株当たり」の1は英語で消えるのが正しい。per 1 share とは書かない
```

**したがって公表訳は実質 16/16 で、ツール側の 15/16 は「人間が正しく落とした数字を
残した」ぶんである。** 数値の保存は絶対条件だが、**この題材では
「多く残したほうが良い」が成り立たない。** 散文の20文（69個すべて実数）とは
性質が違う。

## 5. 照合器を3回直した

この題材では、書いた照合が3回続けて嘘をついた。**いずれも「公表訳の点が低すぎる」
という、あり得ない結果が合図だった。**

```
1回目  公表訳 3/7   -> 全角数字（第１５９期 の １５９）を [0-9] で探していた
2回目  公表訳 8/16  -> ３月 が March になるのを「数字が消えた」と数えていた
3回目  月の規則が自己検査で落ちる
       -> "March 31, 2026" からカンマと空白を除いて "312026" に繋げていた。
          桁区切り（1,609）を外すつもりの処理が、日付を壊していた
```

直すたびに自己検査を先に置き、落ちたら数字を出さずに止めるようにした
（`scratchpath/Score-Compressed.ps1`）。

**「数字が悪いときに疑う順序」の1番で3回連続で当たった。**
圧縮された原文は、散文より照合器を壊しやすい。全角・日付・単位の省略が集中するからである。

## 6. 対照が示したこと

§1 の2行（幅を伝えた／伝えない）は**同じモデル・同じ20行・指示だけ違う**。
その差が、エンジンを替えた差より大きい。

```
指示を替えた差   収まった 5 -> 11 件
エンジンを替えた差 Nani 6 件、幅なしLLM 5 件、公表訳 5 件 ... 動かない
```

**圧縮された原文では、どのエンジンを使うかより、幅を渡せるかどうかが効く。**
そしてそれは YakuLingo が持っていて、DeepL・Nani・Smartcat には見当たらない
種類の機能である。散文の20文でこの差が出なかったのは、**散文には枠が無いから**である。

**ただし、これは「YakuLingo が優れている」の測定ではない。**
測ったのは「幅を伝えると出力が変わる」であって、
**YakuLingo の電文体・短縮経路がこの11/20に届くかはまだ測っていない**（§7）。
届かなければ、機能が在ることは値打ちにならない。
