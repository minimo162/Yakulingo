## 1.【必須】テキスト翻訳の分子0の修正 — CopilotClient.ps1

### 真因（ログ・コード確認済み）
responseTextSoFar() は SOURCE_END: 等のエコー終端マーカーが見つかるまで
'' を返す設計だが、プロンプトが約9,700字あるため **Copilotがユーザー
メッセージのバブルを折りたたみ、innerText に末尾マーカーが現れない**。
結果 cutIndex<0 が恒久化し分子が常に0。従来の抽出処理が cutIndex<0 を
許容していたのはこの折りたたみへの耐性だった。

### 修正
(a) JS 1行: responseTextSoFar の cutIndex<0 分岐を `return ''` から
`return after`（ベースライン以降の全文）に変更。折りたたみ時の可視
エコーは短いため混入は小さく、抽出側の従来互換（uncut続行）も回復する。

(b) PS側の可視エコー控除: バッチごとに初回スライスの answerLengthSoFar
を可視エコー分として記録し、以降は差分を分子にする:
```powershell
if ($sliceCount -eq 1) { $echoBaseLen = $sliceAnswerLen }
$netAnswerLen = [Math]::Max(0, $sliceAnswerLen - $echoBaseLen)
if ($netAnswerLen -gt $maxAnswerLen) { $maxAnswerLen = $netAnswerLen }  # 単調化
$approxChars = $maxAnswerLen
```
- 変数はWaitループのローカル（バッチごとに自然リセット）。
- ratio計測（完了時answerChars）は最終抽出テキスト長を使う現行実装の
  まま変更しない。

## 2.【必須】ファイル翻訳の生成中進捗の表示経路 — ファイルworker

### 現象
kind=file の ratio計測は成功している（後述§4）のに、UI表示は従来の
フェーズ表示のままで生成中の分子/漸進が見えない。

### 調査・修正
1. ファイルworkerのCopilot呼出しに ProgressState が伝搬しているか、
   伝搬している場合に generating フェーズの label/detail/progress が
   ワーカー→state経由でUIに届いているかを確認する。
2. 届いていない場合: ワーカーの進捗パイプ（state書出）に generating
   detail を通す。フェーズ表示（抽出/翻訳/書込）と共存させる場合は
   「翻訳中 (バッチ x/y): 生成中 (分子/分母字目安)」の形で detail に
   合成する。
3. ファイル進捗の全体スケール（シート・アイテムベース）と生成中進捗の
   整合は、既存の batch_progress_start/end 写像に乗せる（テキスト側と
   同一機構のため追加設計不要のはず。届いていない箇所の配線のみ）。

## 3.【必須】プロンプト長ガードと入力切詰め検知

### 背景（Web確認済み）
Copilotの入力上限はライセンス・サーフェス・時期で変動し、128,000字から
8,000字への変更報告が複数ある（E5利用者の8,000字報告もあり）。安定した
公式保証はない。現状のプロンプト固定部は約9,300字のため、8,000字環境に
当たると**入力分割では救えず固定部単独で超過**する。前提が崩れた時に
「無言で切り詰められて誤訳」となるのが最悪ケースであり、検知を最優先する。

### 修正
(a) **fill後の実長検証（最重要・自動検知）**: プロンプト貼付後に入力欄の
実文字数をCDPで読み取り、貼付したプロンプト長と一致しない場合は送信せず
エラーで停止する:
```
PROMPT_TRUNCATED_BY_INPUT_LIMIT: Copilot入力欄でプロンプトが切り詰められ
ました（貼付{N}字→実{M}字）。この環境の入力上限を超えています。
M365 Copilotライセンスの有無・入力上限をご確認ください。
```
- ライセンス無し環境・上限変更の自動検知として機能し、無言の欠落を防ぐ。
- 既存の fillResult 検証に文字数比較を追加する形でよい。

(b) 送信前ガード（設定）: `copilotPromptCharLimit`（既定 0=無効）。
0以外が設定されている場合、promptLength が上限超過なら
テキスト/ファイルともバッチ入力をさらに分割して収まるか試み、
**固定部だけで超過する場合は (a) と同種のエラーで明示停止**する。

(c) 前提の明文化: README と起動時ログに「本ツールは M365 Copilot
ライセンス環境を前提とする（プロンプト固定部約9,300字のため、入力上限
8,000字の環境では動作しない）」を1行明記。

### 対象外（記録）
- 固定部を8,000字未満へ圧縮する案は見送り: 規則（約1,260語）と用語集
  注入をさらに半減させると翻訳品質側の回帰リスクが大きい。8,000字環境の
  正式サポートは需要が実在した時に別途設計（規則の会話コンテキスト分割
  送信等）とする。
