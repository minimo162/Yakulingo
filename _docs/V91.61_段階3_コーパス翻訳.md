# V91.61 段階3: 参考資料コーパスを翻訳へ渡す

作成 2026-08-05

---

## §0 なぜこれを作るのか（前提）

**現状の翻訳には、用語集への依存という根本的な問題がある。**

| 事実 | 帰結 |
| --- | --- |
| 用語集が網羅的でない | 載っていない語は、依頼のたびに違う訳語になる |
| それでもプロンプトは用語集に依存している | 抜けがそのまま訳文の揺れになる |
| 表の項目のように固定化された語は完全一致で拾える | **ファイル翻訳では効いている** |
| それ以外はその時々で表現が変わる | **用語集を書ききることができない**（利用者の判断、2026-08-04） |

用語集を増やして解こうとすると、語を足すたびに別の抜けが出る。
語を追加する作業が終わらないうえ、**追加された語だけが正しくなる**という
局所最適に落ちる。抜けの総量は減らない。

そこで**社内の過去の英文資料そのものを見せる**方式へ移す。
「この語はこう訳す」ではなく「社内ではこう書いている」を示す。
これが段階3 を作る理由である。

**コーパス翻訳は用語集の置き換えを前提にしていない。**
どちらを残すかは、実データで比べてから決める（§6）。

## §1 適用範囲（2026-08-05 に確定）

| 対象 | 判断 | 理由 |
| --- | --- | --- |
| **テキスト翻訳 JA→EN** | **入れる** | 1ジョブが1つのまとまった文章。検索語を1回作れば全体に効く |
| テキスト翻訳 EN→JA | 入れない | コーパスは英語側だけ。英語が入力側にある方向では、社内の言い回しを示す意味がない |
| **ファイル翻訳** | **入れない** | §1-1 |

### §1-1 ファイル翻訳に入れない理由（コードを読んで確認）

- バッチは**文字数**で切られる（`max_chars_per_batch_file`、既定 3000 字）。
  中身は無関係なセル片の寄せ集めで（`[[ID:1]] 売上高` `[[ID:2]] 為替影響` …）、
  **1つの英語検索語では代表できない。**
- 出力は短いラベルである。**数百字の一節を文例として見せても噛み合わない。**
- ファイル翻訳には完全一致の用語集（`Resolve-YakuFileExactGlossaryTranslations`、
  scope `cell-exact`）があり、**プロンプトを経由せずセル全体を決定的に置換する。**
  表の項目が固定化されている領域では、これが最も確実である。

追加往復ゼロで引く道（バッチごとの用語集ヒットの英語側を検索語にする）はあるが、
**用語集に当たった語しか引けない**ため、いま問題にしている「用語集の抜け」は埋まらない。採らない。

### §1-2 精査で判明した、これまでの認識との差

| 認識 | 実際 |
| --- | --- |
| 「ファイル翻訳は用語集、テキスト翻訳は用語集なし」 | **用語集はいま両方に入っている。** `Get-YakuReferenceSection` が `New-YakuTextPrompt` と `New-YakuFilePrompt` の両方から呼ばれている |
| 「FULL と BRIEF を分けていない」 | **テキスト経路だけの話。** テキストは1回の依頼で `FULL_TEXT` と `BRIEF_TEXT` を両方出させている。ファイルは BRIEF のみ。段階6（接続分離）の対象もテキスト経路だけになる |

## §2 経路

```
原文（日本語）
  ↓ ① Copilot に英語の検索語を作らせる      ← ジョブごとに1回。バッチ分割の前
検索語（英語）
  ↓ ② Search-YakuCorpus                     ← 段階2
関連する英語の一節 3件（出典つき）
  ↓ ③ 翻訳プロンプトへ CORPUS_EXAMPLES として添える
訳文
```

**ジョブごとに1回。** バッチごとに引くと Copilot への往復がバッチ数だけ増え、
文例もバッチごとに変わって訳語が揃わなくなる。
分割の前に置くのは、原文全体を見て検索語を作らせるため。

検索語の生成で新規チャットを1度使うので、**最初のバッチは短い待ちへ回す**
（`SkipFreshChatWait`）。往復は増えるが、待ちは丸ごと1回分は増えない。

## §3 決めたこと

### §3-1 設定項目は増やさない

コーパスがあれば使い、無ければ使わない。それだけ。
利用者はコーパスの存在を知らないため、知らない仕組みの入切を出しても選べない。

**ただし「何を参照して訳したか」は出す。** 出典が見えないと、訳語がどこから
来たのか確かめようがない。用語集の pill 行と同じ形にして、行を増やさない。

```
適用された用語: 販促費 → Promo. Costs   …
参照した社内資料: 英文短信/2027-1Q_en.pdf p.3   英文短信/2026-4Q_en.pdf p.1
  ▸ 参照した箇所を見る          ← 既定は畳む。検索語と本文を確かめられる
```

**引けなかったときは何も出さない。** 「参照できませんでした」と言われても
利用者には対処のしようがない。理由は記録にだけ残す。

畳んだ中に出す本文は、**伏せ字を掛けた後のもの**である。
送ったものと違うものを見せると、送信内容を確かめる用を成さない。

### §3-2 引けなければ素通し

`Get-YakuCorpusReference` は**投げない**。次のどれでも空を返し、従来どおり翻訳する。

| 理由 | 状況 |
| --- | --- |
| `direction` | EN→JA |
| `no-corpus` | コーパスが配られていない |
| `no-terms` | Copilot が検索語を作れなかった |
| `no-hits` | 引いたが当たらなかった |
| `error` | 往復が失敗した |
| `not-loaded` | `CorpusReference.ps1` が読み込まれていない経路 |

**警告も出さない。** 利用者が知らない仕組みの失敗を見せても、対処のしようがない。
理由は記録にだけ残す。

`not-loaded` は依存関係の保険である。`Translation.ps1` を読み込むが
Corpus 系を読み込まない経路（別ランスペース・ワーカー・部分的に読み込む回帰テスト）で
翻訳が止まらないようにする。**「コーパスは足しであって前提ではない」を、
依存関係の面でも守る。**（読み込む側も揃えたが、揃え忘れで止まらないようにする）

### §3-3 文例の数字は伏せる

文例の数字は `#` に置き換えてから送る。

**V91.60 の `【N1】` は使わない。** 原文側のプレースホルダーと名前空間が衝突し、
「SOURCE にある token と同じ数だけ出力に現れること」という規則が文例のぶんだけ狂う
（要件整理 §6-4 で未解決としていた問題）。文例に必要なのは言い回しであって数字ではない。

いまのコーパスは開示済み資料だけなので数字を送っても差し支えないが、
**過去 ECM 資料を入れる段階5 では伏せることが前提になる。**
先に伏せておけば、そのときの判断はデータの入れ替えだけで済む。

なお管理画面「引けるか試す」では伏せない。管理者が中身を判断する場だからである。

### §3-4 検索語を作らせる依頼にもマスキングを効かせる

検索語生成でも原文を Copilot へ送る。**ここを素通しにすると、V91.60 の
「数値を外部へ出さない」保証がこの経路だけ抜ける。**
`New-YakuNumericMaskMap -Location 'corpus-query'` を通してから送る（マスク表は使わないので捨てる）。

V91.60 の回帰に、**外部送信の経路が増えたらマスクを通っていることを確かめる検査**を足した。
経路を足すたびに手で思い出す話にしない。

### §3-5 キャッシュ鍵に文例を含める

文例が変われば訳文も変わる。鍵に入れないと、**文例なしで作った訳文を
文例ありの依頼へ返してしまう。** `corpus-v9161:<文例のハッシュ>` を鍵へ足した。

## §5 受容基準

1. **JA→EN のテキスト翻訳でだけ**文例が入ること
2. EN→JA では引かないこと（Copilot への往復も発生しないこと）
3. **ファイル翻訳を一切触っていないこと**
4. コーパスが無いとき、**往復を1回も増やさない**こと
5. 検索語が作れない / 当たらない / 往復が失敗したとき、**素通しで従来どおり訳せる**こと
6. `CorpusReference.ps1` が読み込まれていなくても翻訳が止まらないこと
7. 検索語生成の依頼が**マスク済みの本文**を送ること（原文の数値が出ないこと）
8. 文例の数字が伏せられていること。`【N】` 形式を使っていないこと
9. 文例に**出典（資料名とページ）が必ず付く**こと
10. 文例の有無でキャッシュ鍵が変わること
11. **設定項目を増やしていない**こと。一般利用者の画面に現れないこと
12. 既存の回帰がすべて通ること

回帰は `app/tools/Test-YakuV9161CorpusReference.ps1`。

## §6 実データで決めること（未確定）

**用語集を残すかどうかは、まだ決めない。**

テキスト経路の用語一貫性（テンプレートの R3、FULL と BRIEF で同じ訳語を使う規則）は
GLOSSARY 節に寄りかかっている。外すと何が崩れるかは、読むだけでは分からない。

段階3 は**用語集を入れたままコーパスを足した状態**で出す。そのうえで比べる。

| 比べるもの | 見る点 |
| --- | --- |
| 用語集あり + コーパス（いまの状態） | 基準 |
| コーパスのみ（`use_bundled_glossary` を切る） | 用語集を外して訳語が崩れるか。崩れないなら用語集は不要 |

外すのは1行の変更で済む。**狙いどおり用語集が要らないと分かってから外す。**

そのほか、実データを見てから決めること:

| 事項 | いまの値 | 決め方 |
| --- | --- | --- |
| 文例の件数 | 3件 | 多いと原文より文例が長くなり、依頼の焦点がぼやける |
| 1件あたりの長さ | 600字 | 同上 |
| 検索語の上限 | 12語 | 多いと当たりが散り、どの一節も同じくらいの得点になる |
| 一節へ切る資料の数 | 上位8件 | 段階2 の `-DocumentCandidates` |
| 往復が1回増える体感 | 未計測 | 短文ほど相対的に重い。許容できなければ、短い原文では引かない判断もありうる |
