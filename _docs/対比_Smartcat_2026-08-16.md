# 対比: YakuLingo と Smartcat（2026-08-16 時点）

**これは機能表ではない。** 機能を数えて並べると「闇鍋的に機能を追加する」ほうへ
寄る。ここに載せるのは**実際に測った差**だけで、測っていないものは
「未測定」と書く。測っていないものを「同等」とも「不足」とも書かない。

停止条件は「市販ツールと同じ品質水準」である。それは機能の数ではなく
**同じ資料を訳したときの結果と手間**で決まる。その測定はまだしていない
（§4）。この文書はその前段として、いま何が分かっていて何が分かっていないかを
1か所に集めたものである。

---

## 1. 測定済み: そろっているもの

| 項目 | Smartcat（実測） | YakuLingo（実装） | 出典 |
| --- | --- | --- | --- |
| あいまい一致に「%」 | 出す | 出す | `_docs/測定_一致率_2026-08-16.md` |
| 帯の段 | 100 / 85-99 / 85未満 の3段、色分け | 同じ3段。**塗りの形も3種類**にして色だけに頼らない | 同上 |
| 一致率の尺度 | 帯（75/85/95/99/100/101）を前提 | 編集距離。同じ帯で読める | 同上 |
| 差分の表示 | Match difference（過去訳の原文との差を色で） | 原文側に印（`diffMarkup`） | `www/assets/cat.js` |
| 完全一致の下訳 | 自動挿入。**確定はしない** | `翻訳メモリで下訳する` | `cat.html:253` |
| コンコーダンス | Concordance search タブ | `文脈` タブ / `Ctrl+K` | `cat.html:368` |
| 点検 | QA check タブ | `数字の点検` タブ / `F8` で一覧 | `cat.html:367` |
| プレビュー | Preview タブ（下部・可変） | `体裁で見る`（**別ダイアログ**） | `cat.html:419` |
| 行の結合・分割 | あり | `Alt+M` / `Alt+K` / `Alt+S` | `cat.html:253` |
| 検索・置換 | Search in source / target | `Ctrl+F` / `Ctrl+H` | 同上 |
| 絞り込み | State / Critical errors / Add filters | 確認状態・点検の指摘で絞る | `cat.html:275` |

**キー割当は YakuLingo のほうが厚い。** 確定して次へ（`Ctrl+Enter`）、前後の行
（`Alt+↑↓`）、候補を番号で挿入（`Ctrl+1〜9`）に加えて、**原文の数字を一覧に
出して番号で入れる**（`Ctrl+D` → `1〜9`）がある。これは数値の打ち直しを
なくすためのもので、Smartcat には見当たらなかった（**未確認**。
アイコンに名前が付いておらず、合成イベントでツールチップが出ないため
列挙できなかった。人手で確かめる必要がある）。

## 2. 測定済み: 足りないもの

| 項目 | Smartcat（実測） | YakuLingo | どう効くか |
| --- | --- | --- | --- |
| プレビューの置き場 | **下部に常設**。4pxの仕切りで広げられ、**選択に追随**して赤枠が動く | 別ダイアログ。開くと格子が見えない | 訳しながらの手がかりにならない |
| プレビューの重さ | 軽い | 全シート×2回＋前後の検証。**1シートだけの軽い経路が無い** | 常設にする前提が無い |
| 履歴 | Revisions タブ | 無し | 「誰がいつ何を変えたか」を追えない |
| 行ごとの覚書 | Segment comments タブ | 無し | 申し送りができない |
| 資料全体の覚書 | Document comments タブ | 無し | 同上 |
| 点検の無視 | 指摘ごとに IGNORE の箱 | 無し | §3 参照（意図した差） |

出典: `_docs/測定_一致率_2026-08-16.md`、メモリ `smartcat-measured-behaviour`、
`yakulingo-startup-and-preview`。

## 3. 意図した差（そろえない）

| 項目 | Smartcat | YakuLingo | 理由 |
| --- | --- | --- | --- |
| 数値の不一致 | **黄色い警告。確定できる**＋IGNOREできる | **error。書き出しを止める** | 決まり「数値が抜けた訳は警告ではなく欠陥。意図した省略かを利用者に判断させない」 |
| タグ欠け | Critical。確定できない | 同様に error | 一致している |
| `MinScore` | 選べる最低が 0.75 | **0.70** | 上げると「数値だけ違う」候補（実測 0.733）が消える。それが決算翻訳でいちばん使い回せる型 |
| 外部送信 | そのまま送る | **数値をマスクして送る** | 利用者の判断（`_docs/決定_実装優先と固有名詞マスク_2026-08-14.md`） |

実測した文面: `Tag <1> must be present both in source and target`（止まる）、
`Dates and numbers in source and target do not match`（止まらない。行は緑）。

## 4. 未測定（ここが埋まるまで「同等」とは言えない）

**いちばん大きいのはこれ。** 同じ資料を両方で訳して、結果と手間を比べていない。

- **同じ資料での通し比較。** 題材は揃っている（実在を確認済み）。

      _docs/mazda_2025_full_year_results_ja_20250512.pdf   過去訳の原文
      _docs/mazda_2025_full_year_results_en_20250512.pdf   過去訳の訳文
      _docs/mazda_2027_Q1_kessan_tanshin_20260804.pdf      今回訳す分

  測るのは (a) 一致率が実際の手直し量と比例するか (b) 出来上がりの差
  (c) かかった時間

  **(a) は 2026-08-16 に測り終えた。** 2027年Q1 の正解訳が無くても、
  2025年の日英ペアだけで測れる形に組み直した（数の並びを錨に日英を対にし、
  1組ずつ取り置いて残りをTMとし、引けた過去訳の英文と正解英文の差を測る）。
  200組で**全4帯とも単調**に下がった（0.75-0.84 で 0.093、0.50未満 で 0.596）。
  **一致率は手直し量を言い当てており、0.70 という線も妥当だった。**
  出典 `_docs/測定_一致率_2026-08-16.md`。

  **(b)(c) は残る。** これは両方のツールで実際に訳す作業が要る。
- ~~**一致率の実文書での挙動。**~~ **2026-08-16 に測った。** 2025年の資料（783行）を
  TM にして 2027年Q1（441行）を照合したところ、過去訳が引ける行が
  **103 → 129（+25%）**。増えたのは四半期ごとに必ず出る短い定型行だった
  （出典 `_docs/測定_一致率_2026-08-16.md`）。
  **ただし「一致率と手直し量が比例するか」はまだ測れていない**（正解訳が要る）
- Smartcat のツールバー各操作（アイコンに名前が無く、列挙できなかった）
- 用語集の扱いの対比
- Excel の往復で、Smartcat が部分書式をどう保つか（メモリに「タグ対にする」と
  あるが、往復後の1文字ずつの実測はしていない）
- 速さの対比（Copilot の応答時間を含む）

## 5. この文書の使い方

- **§4 が埋まるまで、停止条件は判定できない。** 機能表の充足では代わりにならない
- §2 を埋めるときは、機能を足す前に「その資料でどれだけ手間が減るか」を測る
- §3 は測って決めた差である。緩めるときは同じだけの根拠を要る
