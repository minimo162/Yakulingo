# V91.61 段階2: 索引と語彙検索

作成 2026-08-05

段階1（`_docs/V91.61_修正指示書_参考資料コーパスの作成と配布.md`）で、
英語資料の Markdown がローカルへ配布されるところまで動いた。
段階2 は、それを**引ける形にする**ところまでを担う。

**この段階では翻訳経路へ差し込まない。** 差し込みは段階3（Agentic 検索）で行う。
ここで作るのは検索器と、それが実データで機能しているかを管理者が確かめる手段だけである。

---

## §1 前提（動かさない決定）

| 決定 | 出典 |
| --- | --- |
| コーパスは**英語側だけ**。日本語との対応づけ（文アライメント）を持たない | 要件整理 §13-4 |
| **埋め込みを使わない。** 利用者端末にモデルもランタイムも置かない | 要件整理 §6-1 |
| 日本語の原文から英語コーパスを引く橋渡しは、**Copilot に英語の検索語を作らせる** | 要件整理 §13-4 |
| 検索層は**差し替え可能**にしておく（後から埋め込みを差し込めるように） | 要件整理 §6-1-4 |
| 一般利用者の起動経路に、索引の処理を一切入れない | 修正指示書 §7-3 |

語彙検索で足りるという裏づけは要件整理 §13-5（AAAI 2026、FinanceBench で
語彙検索がベクトル検索を 6 ポイント上回った）。

## §2 作ったもの

### §2-1 `app/src/CorpusSearch.ps1`

| 関数 | 役割 |
| --- | --- |
| `Get-YakuCorpusSearchDir` | 引く先を決める。配布済みコーパス → 無ければ管理者の `corpus-build` |
| `Get-YakuCorpusTokens` | 英語の一節を索引語へ分ける |
| `Split-YakuCorpusPassages` | Markdown を「引ける単位」へ切る |
| `New-YakuCorpusIndex` | 索引を作る |
| `Test-YakuCorpusIndexCurrent` | 索引がコーパスに追いついているか |
| `Initialize-YakuCorpusIndex` | 無い・古いときだけ作る |
| `Get-YakuCorpusBm25Score` | **順位づけ。ここだけ差し替えれば方式を変えられる** |
| `Search-YakuCorpus` | 検索の入口。**呼び出し側はこの戻り値だけを見る** |

### §2-2 一節への切り方

- **ページ境界（`<!--yaku-page:N-->`）を越えない。** どの資料の何ページから引いたかを示すため。
- 空行で段落へ切り、目安 900 字までまとめる。1行だけの見出しや表の1行は文例にならない。
- 60 字に満たない一節は捨てる。

### §2-3 索引語の取り方

- 小文字化し、英数字以外で切る。**日本語の形態素解析も文字 N-gram も要らない**（英語だけなので）。
- **数字だけの語は落とす。** 「2026」で引いても言い回しは見つからない。雑音になる。
  （翻訳経路の数値は V91.60 でマスクされるため、検索語にも現れない）
- 英語の機能語（the / of / and …）は落とす。財務資料は定型表現が多く、
  残すとどの一節も同じくらい当たってしまう。

### §2-4 索引の置き場所

```
<データディレクトリ>\corpus-index\<コーパスの版>\
  ├─ meta.tsv       書式・署名・件数・平均長
  ├─ passages.tsv   id, データベース, 出典, ページ, 語数, 本文
  └─ postings.tsv   索引語, 文書頻度, "id:出現数 id:出現数 …"
```

**コーパスの中（`corpus\<版>\`）へは書かない。** そこは `bootstrap.ps1` が
版ごと入れ替える領域であり、派生物を混ぜると「古い版」として掃除されてしまう。

JSON ではなく TSV にしたのは、PowerShell 5.1 の `ConvertFrom-Json` が
数MB で目に見えて遅く、検索のたびに読むには重いためである。

### §2-5 作り直しの判定

台帳の「版・更新時刻・件数」を署名にして `meta.tsv` へ持つ。一致すれば作り直さない。
索引の書式（`schema`）が変わったときも作り直す。

### §2-6 管理画面「引けるか試す」

`-Admin` のときだけ `/api/admin/corpus/search` を登録する。
**一般利用者の画面には出さない**（利用者向けの表示は段階4 で初めて検討する）。

## §3 実測（2026-08-05）

検証環境は PowerShell 7.4 / Linux。**実機の Windows PowerShell 5.1 では 2〜3 倍を見込む。**

コーパス: 資料 100 件 / 1,500 ページ / 6.5 MB / 一節 6,000 件 / 索引語 8,074 件

| 処理 | 実測 |
| --- | --- |
| 索引の作成（版が変わったときだけ） | **9.5 秒** |
| 検索1回 | **0.3 〜 0.9 秒** |
| 索引が最新かの確認 | **6 ミリ秒** |
| 索引の大きさ | 10.5 MB（コーパス本体とは別。配布物には含めない） |

### §3-1 途中で潰した遅さ

最初の実装は**索引作成 89 秒 / 検索 7.4 秒**だった。原因は3つ。

| 原因 | 実測 | 直し方 |
| --- | --- | --- |
| **`\| Out-Null` をループの中で使っていた** | `List.Add` 72万回で **100 秒**（`[void]` なら 1.7 秒） | ループ内は `[void]` にする |
| 語ごとに正規表現を回していた | 120 万語で数十秒 | 切り分けは正規表現1回、語ごとは文字比較 |
| 当たった一節をすべて復元していた | 6,000 件で 7 秒 | 上位に残す数件だけ復元する |

**`| Out-Null` の費用は呼び出しごとにパイプラインを1回組み立てる分である。**
ループの外では既存コードに合わせてよいが、**繰り返しの中では使わない。**
`CorpusSearch.ps1` の冒頭にこの理由を書いてある。

## §4 受容基準

1. 索引が**コーパスの中へ書かれない**こと（`bootstrap.ps1` の掃除に巻き込まれない）
2. ページ境界を越えた一節ができないこと
3. 数字だけの語・機能語が索引語にならないこと
4. 出典（データベース・資料・ページ）が必ず付くこと
5. 得点の高い順に並び、同点でも順序が揺れないこと
6. データベースで絞り込めること（括弧・半角カナを含む名前でも）
7. 当たらないときに**0 件を返す**こと（作り話をしない）
8. コーパスが無い / 索引が作れないときに**0 件を返し、落ちないこと**
9. 索引が最新なら作り直さないこと
10. コーパスが変わったとき・索引の書式が変わったときに作り直すこと
11. `-Admin` を付けないとき、検索の経路が**登録されない**こと
12. **翻訳経路（`Translation.ps1` / `FileTranslation.ps1`）に差し込まれていない**こと
13. 一般利用者の画面に現れないこと
14. 既存の回帰がすべて通ること

回帰は `app/tools/Test-YakuV9161CorpusSearch.ps1`。

## §5 段階3 へ引き渡すもの

```
原文（日本語）
  ↓ ① Copilot: 「この内容を英語資料から探すならどんな語で引くか」   ← 段階3
検索語（英語）
  ↓ ② Search-YakuCorpus                                          ← 段階2（ここまで完了）
関連する英語の一節 数件（出典つき）
  ↓ ③ Copilot: 「社内資料ではこう書いている。これに倣って訳せ」      ← 段階3
訳文
```

段階3 で決めること:

- 検索語の生成を**翻訳ジョブごとに1回**にする（要件整理 §6-1-3）。バッチごとにしない。
- 引けなかったときに**素通しで従来どおり訳す**こと。コーパスは足しであって前提ではない。
- 文例をプロンプトへ入れる形（何件・何字まで・出典を見せるか）。
- 検索1回の費用（実機で 1〜2 秒を見込む）を、どのタイミングで払うか。

## §6 積み残し

| 事項 | 判断 |
| --- | --- |
| 検索のたびに `passages.tsv` を読み直す | 実測 0.3〜0.9 秒。ジョブごとに1回なら許容。必要なら常駐側で持ち回る |
| 同義語・言い換えへの弱さ | **段階3 の Agentic 検索で補う**のが元の設計（要件整理 §6-1-4） |
| 埋め込み検索 | 塞いでいない。`Get-YakuCorpusBm25Score` の対を足せば差し込める |
| 日本語側の資料 | 扱わない。英語側だけという決定は動かさない |
