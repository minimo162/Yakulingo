# V91.32 修正指示書 — 期待応答長の実測校正（進捗係数の種別分離）

ベース: V91.31（プロンプト再整理・実測進捗版）
対象: Translation.ps1（expectedChars計算）/ 設定既定値
根拠: yakulingo.log の actualRatio 実測4件（2026-07-21、全てkind=text・単一バッチ）
      30字→8.067 / 366字→4.268 / 400字→5.483 / 1,832字→4.227

---

## 0. 実測から分かったこと

- V91.31の既定係数0.6は実態と桁違い（テキスト翻訳は複数訳文案＋BRIEFを
  返すため応答は入力の4〜5倍）。現状のままだと expectedChars 過小で
  応答序盤に charBased が88に到達し「序盤張り付き」が再発する。
- 超短文（30字）で比率8.1に跳ねるのは、応答の固定オーバーヘッド
  （ラベル・定型部）が入力に比例しないため。**傾き＋切片のアフィン構造**
  であり、実測4点は `expected ≈ 150 + input × 4.5` でフィットする
  （1,832字→推定8,394 vs 実測7,744 / 30字→285 vs 242 / 400字→1,950
  vs 2,193 / 366字→1,797 vs 1,562）。
- 誤差の方向性: expectedChars **過大は安全**（バーが遅めに進み完了時に
  少し跳ぶだけ）、過小は序盤張り付き（悪）。推定は上側に寄せる。

## 1.【必須】expectedChars をアフィン式・種別別に変更 — Translation.ps1

### 現行
```powershell
try { $ratio = [double]$Settings.copilotAnswerRatio } catch { $ratio = 0.6 }
$ProgressState['batch_expected_chars'] = [Math]::Max(1.0, ([double]$batch.CharCount * $ratio))
```

### 修正後
```powershell
# 種別別のアフィン推定: expected = base + input × ratio
if ($Kind -eq 'text') {
    $ratio = 4.5; $base = 150.0
    try { if ($Settings.copilotAnswerRatioText) { $ratio = [double]$Settings.copilotAnswerRatioText } } catch {}
    try { if ($Settings.copilotAnswerBaseText)  { $base  = [double]$Settings.copilotAnswerBaseText } } catch {}
} else {
    $ratio = 1.5; $base = 0.0   # ファイル翻訳は暫定値（下記§2）
    try { if ($Settings.copilotAnswerRatioFile) { $ratio = [double]$Settings.copilotAnswerRatioFile } } catch {}
    try { if ($Settings.copilotAnswerBaseFile)  { $base  = [double]$Settings.copilotAnswerBaseFile } } catch {}
}
$ProgressState['batch_expected_chars'] = [Math]::Max(1.0, $base + ([double]$batch.CharCount * $ratio))
```
- 既存設定キー copilotAnswerRatio は廃止（読み替え不要。設定に残って
  いても無視される旨をリリースノートに1行）。
- バッチ2以降の同ジョブ内学習（実測比平均での上書き）は従来通り維持。
  学習側も `answerChars = base + input×learnedRatio` に合わせる必要は
  なく、実測比そのもの（answer/input）で上書きしてよい——バッチ2以降は
  同一文書内で切片の影響が安定するため。

## 2.【受入時確認】ファイル翻訳の係数校正

ログにはまだ kind=file の actualRatio 実測が無い（V91.31配備後に
ファイル翻訳が未実行）。暫定値 ratio=1.5 / base=0 で配備し、
**次回のExcel翻訳で actualRatio ログを確認**して乖離が大きければ
設定キー（copilotAnswerRatioFile）で調整する。番号付きアイテム形式は
入出力がほぼ1対1のため1.2〜1.8に収まる見込み。

## 3. 受入基準

1. 単一バッチのテキスト翻訳（100字前後・400字前後・2,000字前後の3水準）
   で、応答生成中にバーが8〜92%区間を漸進し、序盤の88%張り付きが
   発生しない
2. 各実行の actualRatio と expectedChars の乖離が概ね±50%以内
   （expected過大側の superare は許容）
3. 超短文（数十字）でも序盤張り付きが起きない（切片150の効果確認）
4. 次回ファイル翻訳で kind=file の actualRatio を確認し、必要なら
   設定キーで校正（コード変更なしで調整可能なことの確認）
