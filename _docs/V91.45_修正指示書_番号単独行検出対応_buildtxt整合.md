### 不発の機構（特定済み）

同ジョブで番号ずれ（BRIEF=4,5,6）が再現したが、復元はskip:

```
Text numbered headings mismatch; restore skipped. style=full source=<redacted> target=0
Text numbered headings mismatch; restore skipped. style=brief source=<redacted> target=0
```

**target=0** が核心。訳文側の番号見出し検出がゼロ件のため、V91.44の新ガード
（件数一致が前提）に到達する前に空振りしている。

原因は訳文の実出力形態。今回の抽出結果は番号が**単独行**になる:

```
4.
Australian CO2 Regulation Credit Purchase Impact in FY27/3
```

これはextractText（CopilotClient.ps1）のol番号挿入時、`<li>`内の先頭に
空白テキストノード（改行含む）があると「4. 」の直後に改行が残り、番号と
見出しテキストが行分離するため。検出regex
`^\s*(?:#{1,6}\s+)?(\d+)([\.．])\s+(.+?)\s*$` は同一行にタイトル文字列
（`\s+(.+?)`）を要求するのでマッチしない。V91.44の単体テストは「N. Title」
形式のみで構成しており、この形態が盲点だった。

さらに置換側の headingPrefixRegex `^(\s*(?:#{1,6}\s+)?)\d+([\.．])(\s+)` も
末尾 `(\s+)` を要求するため、検出を直しても単独行「4.」の置換が失敗する。
**検出・置換の両方**の修正が必要。

### build.txt不整合

V91.44パッケージの `app/config/build.txt` が V91.43 のまま（current.txt=V91.44

build.txt更新の明記が無かった指示書側の抜け）。

## §1 Translation.ps1: 番号単独行の検出・置換対応

### §1a 検出regexの緩和（Get-YakuNumberedHeadingSequence 内・1箇所）

置換前:
```powershell
        $m = [regex]::Match([string]$lines[$i], '^\s*(?:#{1,6}\s+)?(\d+)([\.．])\s+(.+?)\s*$')
```
置換後:
```powershell
        $m = [regex]::Match([string]$lines[$i], '^\s*(?:#{1,6}\s+)?(\d+)([\.．])(?:\s+\S.*?)?\s*$')
```

- 「1. Title」（従来形）と「1.」単独行の両方にマッチする
- タイトル部のキャプチャ（旧Groups[3]）は現行コードで未使用のため、
  非キャプチャ化してよい（Number/Separator/LineIndexのみ使用を実装時に確認）

誤爆リスクと抑止:
- 「2020.」等の数値のみ行が見出し扱いされる可能性が広がるが、実復元は
  従来からの前提条件（原文見出し2件以上・**原文と訳文の件数一致**・番号列不一致）
  をすべて満たす場合のみ発動する。原文・訳文で同regexを使う対称性により、
  原文側に同形の行が無ければ件数不一致でskipされる
- 本regexは Get-YakuNumberedHeadingSequence 専用であり、他の呼び出し元が
  無いことを実装時に確認する（V91.44時点で呼び出しはRepair内の2箇所のみ）

### §1b 置換regexの緩和（Repair-YakuNumberedHeadingSequence 内・1箇所）

置換前:
```powershell
        $headingPrefixRegex = New-Object System.Text.RegularExpressions.Regex('^(\s*(?:#{1,6}\s+)?)\d+([\.．])(\s+)')
```
置換後:
```powershell
        $headingPrefixRegex = New-Object System.Text.RegularExpressions.Regex('^(\s*(?:#{1,6}\s+)?)\d+([\.．])(\s*)')
```

- 単独行「4.」（ピリオド後に空白なし・行末）でも置換が成立する
- 「1. Title」形は `(\s*)` が従来どおり空白を捕捉し挙動不変

### §1c 変更範囲の確認

- 変更はTranslation.ps1の上記2行のみ。V91.44で導入したガード条件・ログ・
  呼び出し側（:462）は無変更
- file経路・to_jp経路への影響なし（V91.44指示書の整理どおり）

## 受入基準

1. §1a/§1b: dot-source再現（V91.44と同手法）で以下を確認:
   - 【新形態・本命】source=「1. 題\n2. 題\n3. 題」/ target=「1.\nA\n…\n2.\nB\n…\n3.\nC」
     を各見出し番号4,5,6に差し替えた訳文 → target=3件検出・復元され 1,2,3 に戻る
   - 【従来形の回帰】source=[1,2,3] / target=「4. A / 5. B / 6. C」（同一行形）
     → 復元維持
   - 【repeated回帰】source=[1,2,3] / target=[1,1,1] → 復元維持
   - 【一致時no-op】source=[1,2,3] / target=[1,2,3]（単独行形含む）→ 無変更・ログなし
   - 【件数不一致】source=[1,2,3] / target=2件 → skip＋WARN
   - 【誤爆抑止】原文に番号見出しが無く訳文にのみ「2020.」等の数値行がある
     → 件数不一致でskip（復元されない）
   - 【全角ピリオド】「２．」正規化後の `2．` 単独行で区切り文字保持
2. §1 実機: 番号付き見出し（1. 2. 3.）を含む今回同等のtext翻訳で、
   オフセット発生時に `Text numbered headings restored from source.` ログが

   非発生時は無変更（restoredログなし）
