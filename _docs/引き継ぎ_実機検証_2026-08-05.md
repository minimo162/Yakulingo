## §3 動かし方

### §3-1 起動

共有フォルダに置いてある `.cmd` から起動する。`bootstrap.ps1` が
`%LOCALAPPDATA%\YakuLingo\versions\<build>-<hash>\app` へ複製してから走る。

| ランチャー | 用途 |
| --- | --- |
| `YakuLingo起動.cmd` | 一般利用者。**コーパス作成の画面も API も出ない** |
| `管理者用_コーパス作成.cmd` | 管理者。`-Admin` が付き、`/admin` と `/api/admin/corpus/*` が登録される |

直接動かすなら `V91.61/app/Start-YakuLingo.ps1`（`-Admin` `-Port` `-NoBrowser` を取る）。

### §3-2 置き場所

| 何 | どこ |
| --- | --- |
| 記録 | `%USERPROFILE%\.yakulingo-ps\logs\yakulingo.log` |
| 取り込み結果（管理者） | `%USERPROFILE%\.yakulingo-ps\corpus-build\` |
| 配布用フォルダ | `%USERPROFILE%\.yakulingo-ps\corpus-publish\<日付>\corpus\` |
| 配布済みコーパス（利用者） | `%LOCALAPPDATA%\YakuLingo\corpus\<版>\` |
| アプリ本体の複製 | `%LOCALAPPDATA%\YakuLingo\versions\<build>-<hash>\` |

**アプリは共有フォルダへ書き込まない**（V91.61 の設計上の約束）。
配布用フォルダを共有へコピーするのは人の作業である。

### §3-3 コーパスを配るまで

1. `管理者用_コーパス作成.cmd` を起動
2. 「原本フォルダ」に**英語の PDF** を入れたフォルダを指定 →「読み込む」
   - 直下のフォルダ1つが1データベースになる（直下に置いた PDF は `(未分類)`）
3. 「未取込を取り込む」 — 解析はブラウザ内の WASM（LiteParse）で行う。外部通信なし
4. 「作成」→ `corpus-publish\<日付>\corpus\` ができる
5. **その `corpus` フォルダを共有フォルダ（`YakuLingo起動.cmd` と同じ場所）へ丸ごとコピー**
   - 既に `corpus` があれば上書き（統合）。`current.txt` も入っているので書き換え不要
6. 一般利用者として起動すると `%LOCALAPPDATA%\YakuLingo\corpus\<版>\` へ複製される

## §4 見てほしいこと（優先順）

### §4-1 コーパス翻訳が効いているか ← **最重要**

出発点の問題は「**用語集が網羅的でないのに、それに依存している**」だった。
コーパス翻訳はその答えとして作ったので、**ここが効いていなければ全部が空振りである。**

**切り分けのため、順番に見ること。**

1. **コーパスを配る前に**、テキスト翻訳（JA→EN）を数本流して結果を控える
2. 英文短信を**数件**（1件では候補の絞り込みが働かない）取り込んで配る
3. **同じ原文**をもう一度訳す

見るもの:

- 結果画面の「**参照した社内資料**」に出典（資料名 p.ページ）が出るか
- 「参照した箇所を見る」を開いて、**引かれた一節が訳文に反映されているか**
- 使われた検索語が妥当か（機能語や数字は落ちるので、入力とは違う）

引けなかったときは**何も表示されない**（仕様）。理由は記録に出る:

```
Corpus reference applied. terms=... hits=... queryMs=... searchMs=... sources=...
Corpus reference skipped. reason=no-corpus | no-terms | no-hits | error
```

### §4-2 BRIEF の略語が揃っているか

`acd39f3` で、文脈に依らない略語 49 件を**アプリ側で当てる**ようにした。
プロンプトの指示（確率的）ではなく、後処理（確定的）である。

見るもの:

- `January` → `Jan.`、`approximately` → `approx.`、`operating profit` → `OP`、
  `fixed costs` → `FC`、`with` → `w/` などが **BRIEF に必ず**現れるか
- **FULL は spelled-out のままか**（FULL には当てていない）
- **引用符の中が変わっていないか**（BRIEF 規則 Q1 を守るため触っていない）
- 誤変換が無いか（`within` が `w/in` になる等は回帰で塞いだが、実文で確認したい）

### §4-3 残っている訳語の揺れがどの語で起きているか

これは**次の判断材料**である。FULL と BRIEF の並列化（往復を増やさず速くする案）は、
「訳語の統一をアプリ側で保証できること」が条件になっている。
49 件は確定したが全体は覆えていない。

**揺れている語を控えておくと、次に何を確定させるべきかが決まる。**

### §4-4 速度

段階3 で **Copilot への往復がジョブごとに1回増えている**（検索語の生成）。

- 短い原文ほど相対的に重い
- 許容できなければ「短い原文では引かない」判断もありうる
- 記録の `queryMs` と `searchMs` に実測が出る

### §4-5 用語集に無いラベルの一覧（ファイル翻訳）

ECM 資料を1本訳すと、警告欄に「**用語集に無いラベル**」が出る。

- **件数が現実的か**（数件なら運用が回る。数十件出るなら判定が緩い）
- **上位が本当に用語集へ足したいものか**（短い順に並ぶ。誤検出は下へ沈む設計）

### §4-6 用語集をプロンプトから外せるか

設定 `use_bundled_glossary` を切ると、プロンプトの GLOSSARY 節が消える
（**ファイル翻訳の完全一致置換も止まる**ので注意）。
コーパスがあれば訳語が保てるか、比べて判断する材料になる。

## §5 触るときの決まり（守らないと壊れる）

### §5-1 文字コードと改行

| 対象 | 決まり |
| --- | --- |
| `.ps1` / `prompts/*.txt` / `www/` / `config/settings.template.json` | **UTF-8 BOM 付き** |
| 改行 | **ファイルごとに CRLF と LF が混在している。既存のまま保つ** |
| `.cmd` | ASCII のみ・BOM なし・CRLF |

改行は `app/tools/eol-baseline.txt` で固定してある。
意図して変えたときだけ `Check-Encoding.ps1 -UpdateEolBaseline` を実行し、
**差分が意図したファイルだけか確認すること。**

過去に、パッチ処理が LF のファイルを丸ごと CRLF へ変換して全行が差分になった事故がある。
