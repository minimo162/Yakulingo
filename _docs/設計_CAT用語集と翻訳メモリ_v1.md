# CAT用語集・翻訳メモリ修正仕様 v1

## 1. 目的

資料翻訳で、用語の統一と過去文の再利用を別の機能として扱う。

- 用語集（用語ベース）は、文中の語・短い表現と推奨訳を管理する。
- 翻訳メモリは、利用者が機械チェック後に確認した文・セグメント全体を管理する。
- 前回版は、利用者がその作業へ明示的に読み込んだ場合だけ、用語集・翻訳メモリと区別し、出典付きで表示する。
- ちょっと翻訳は、用語集・翻訳メモリ・前回版を参照も保存もしない。

### 1.1 配布とデータ所有権

配布物の再利用資産は空とする。会社・資料固有の用語集、翻訳メモリ、コーパス、固有名詞一覧を同梱しない。内部資料由来の表現と外部公表資料由来の表現が、出所や利用意図が分からないまま別の翻訳に混入することを防ぐ。

通常の資料翻訳が参照する再利用資産は次の3種類に限定する。

1. 利用者が登録した「この資料だけ」または「今後の資料でも使用」の用語
2. その端末で利用者が機械チェック後に「確認済み」にした翻訳メモリ
3. 利用者が現在の作業へ明示的に読み込んだ前回版

アプリの更新時は利用者の用語、翻訳メモリ、旧個人用語集の移行元、プロジェクト、既存の参照履歴を削除・初期化・再計算しない。旧コーパスが存在しても自動参照せず、物理削除は行わない。

数値マスキング、数値・単位の整合性検査、`億円` から `oku` への決定論的変換は再利用資産ではなくアプリの処理規則であり、空の用語集でも維持する。

## 2. 用語集

### 2.1 レコード

用語は概念単位で保存し、次を持つ。

- 安定した用語IDと版
- 翻訳方向
- 日本語・英語それぞれの推奨形、許容形、禁止形
- 適用範囲: `この資料だけ` または `今後の資料でも使う`
- 用途: 文中用語またはセル全体の固定訳
- 機械チェック: 必須または参考
- 補足、登録元資料、場所、ページ、セグメント
- 有効・無効状態、作成・更新時刻、改変検出用reference ID

優先順位は、この資料の用語、利用者が「今後の資料でも使用」として登録した用語の順とする。配布物由来の読取専用用語は設けない。同じ優先順位で推奨訳が競合した場合は自動選択せず、確認を止める。

### 2.2 登録

CAT行の原文と訳文で文字列を選択し、「用語を登録」から登録する。

- 原文の用語と推奨訳は必須。
- 既定の適用範囲は「この資料だけ」。
- 許容する別訳、使用しない訳、補足は任意。
- 選択がない場合、短いセル見出しだけはセル全体を初期値にできる。
- 長い文章全体を用語として登録しない。

登録後は該当する既存行を再検査する。訳文を黙って変更せず、影響した確認済み行だけを再確認対象へ戻す。
登録済み用語は候補カードから修正または無効化できる。いずれも版を追記して履歴を残し、プロジェクト保存に失敗した場合は新しい用語状態を有効なまま残さない。

### 2.3 候補と挿入

候補APIと画面を二つに分ける。

- 用語: 原語、推奨訳、許容訳、禁止訳、適用範囲を表示する。訳文のカーソル位置または選択範囲へ、語だけを挿入する。
- 参考訳: TMと、その作業へ読み込んだ前回版の原文・訳文・一致率・資料名・場所・ページを表示する。利用者の明示操作で訳文全体を置き換える。配布コーパスや出所不明の過去資料は表示しない。

用語候補を全文置換APIへ渡しても、サーバーで拒否する。用語挿入で文全体を単語一つにできないことを必須境界とする。

用語候補が空のときはエラーとせず、必要な語を原文と訳文から選んで「用語を登録」すると、この資料または今後の資料で使えることを候補欄で説明する。TM候補が空のときは、訳文を「確認済み」にするとその端末のTMへ自動保存され、次の資料から候補になることを説明する。初回起動時に内部／外部や公表／非公表の分類を選ばせない。

### 2.4 CAT生成条件

CATで訳案を作るとき、その原文に実際に一致した必須用語だけを用語条件としてCopilotへ渡す。TMと前回版の全文は自動投入しない。

- 数値を含む用語条件は、数値保護契約を満たせない場合は送信条件に使わず、ローカル機械チェックだけで扱う。
- 利用した用語IDと版をセグメントへ記録する。
- 用語条件変更時は以前の用語スナップショットに基づく機械チェックを失効させる。

### 2.5 機械チェックと例外

次を確認を止める問題とする。

- 必須用語の推奨形・許容形が訳文にない。
- 禁止形が訳文にある。
- 同順位の用語が競合している。
- 用語DBを正常に検査できない。
- 用語スナップショットが機械チェック後に変わった。

文脈上別の表現が適切な場合は、「この行では別の表現を使う」で例外を記録する。例外は用語ID・版、セグメントID、原文ハッシュ、訳文ハッシュ、理由、代替表現に拘束し、どれかが変われば失効する。

## 3. 翻訳メモリ

### 3.1 保存

機械チェックに合格し、利用者が「確認済み」にしたセグメントだけを保存する。

- 原文、訳文、方向、確認revision
- 資料名、文書内の場所、ページ、project ID、segment ID
- 原文・訳文ハッシュ、安定reference ID
- 保存時刻と有効状態

同じ原文でも、別資料・別セグメントで確認された異なる訳は候補として保持する。同じ確認単位・同じ内容の再保存だけを冪等にする。

### 3.2 検索

- 正規化原文が同じ候補を100%一致として最優先表示する。
- それ以外は文字n-gram類似度で検索し、70%以上を類似一致として表示する。
- 一致率は品質や承認を意味しない。画面では「原文一致率」と明記する。
- 候補には原文・訳文、資料名、場所、ページ、確認日時を必ず表示する。
- 候補挿入後は未確認・機械チェック未実施とし、確認状態を継承しない。

### 3.3 訂正・削除

個人TM候補はreference IDを指定して無効化できる。物理削除せずtombstoneを追記し、以後の検索から除外する。既にその候補を使ったセグメントの参照スナップショットは保持する。

## 4. 保存・監査

CAT projectへ次を保存する。

- 用語スナップショットハッシュ
- セグメントの用語一致、生成時用語、用語例外
- 全文候補の参照利用イベントと、挿入後に編集されたか
- 確認後のTM保存待ちイベント

旧project、旧TM v2、既存のセル完全一致用語は読み取り互換を保つ。旧出典不明TMや改変されたレコードは候補に出さない。

## 5. 主要受入条件

1. 「一過性」と「one-time」を選択し、この資料の用語として登録できる。
2. 別文の「一過性」が用語として表示され、語だけをカーソル位置へ挿入できる。
3. 用語操作で訳文全体が `one-time` に置換されない。
4. CATの訳案作成条件に用語が入り、用語ID・版が記録される。
5. 必須用語が欠けた訳は確認、TM保存、DRAFT出力へ進まない。
6. 明示例外はその行だけに効き、原文・訳文・用語変更で失効する。
7. 用語追加で既存訳を黙って変更せず、影響行だけ再確認対象になる。
8. TMは完全一致と類似一致を別表示し、同一原文の複数訳と出典を保持する。
9. TM候補を無効化すると新しい候補一覧から消えるが、既存の利用記録は残る。
10. ちょっと翻訳は用語集・TM・前回版を読まず、書かず、promptへ入れない。
11. 新規利用者の用語とTMは0件で始まり、配布物由来の候補や固有名詞機械チェックが表示されない。
12. 利用者が登録した文中用語は対象範囲だけで候補・訳案作成条件・機械チェックに使われる。セル全体の固定訳は完全一致セルだけに事前翻訳として使われる。
13. 利用者が確認済みにした訳は別の資料でTM候補になるが、機械下訳・候補挿入・前回版読込だけではTMが増えない。
14. 旧配布コーパスや管理者作業用コーパスが存在しても新規候補に出さず、物理削除も行わない。
15. `oku`、`k units`、数値マスキング、数値・単位チェックは、用語やTMが0件でも従来どおり動作する。
